## 0. 先建立整体认知

本轮把设计文档的多项承诺落成了代码，四块相对独立但共享架构风格：

| 板块 | 解决的缺口 | 权威 ADR |
|---|---|---|
| 多任务调度 + 多 Agent | "一次对话多个控件"从无编排到有规划/扇出/汇总 | ADR-006/007 |
| M08 出护栏 + 真沙箱 | 不可信代码在隔离容器里编译/渲染/断言后才交付 | M08 模块文档 |
| 记忆/上下文补齐 | ADR-009 三项前置（generation_task/bundle_ref/task_turn） | ADR-009 |
| 快照 + 设备模拟 | jsdom 无像素布局、设备 API/续航压制缺检测 | ADR-010 |

**统一模式**：纯函数判定层（无副作用、零模型） + 可注入端口（Protocol） + 接线层做副作用。生产端口缺配置 fail-fast，测试注入 `tests/support` 的桩。

## 5. 阶段 5 · 快照缺口与 ADR-010（523 行）

### 5.1 设备模拟 `device_sim/detector.py`（186 行）
`detect_violations()`（:101）五类违规：白名单外 API=`dangerous_api`、最小间隔/配额违反=`high_frequency`、全量渲染超阈=`render_storm`、限流后短窗重试=`retry_storm`、耗时>ANR=`long_task`。`load_limits()`（:76）读契约 fail-closed。**只读零副作用**，重构建议随 `Violation.remediation` 返回。

`installDeviceMock()` 在 `window.eval(compiled)` 前装 `window.widgetDevice`（限流/Doze/配额返回 `{ok,code}`），每次调用记入 `window.__deviceCalls`，report 顶层输出 `device_calls`（三路径均输出，空为 `[]`）。契约由 Python payload 注入（`:92` 优先用 payload，消除容器内内嵌副本漂移）。

### 5.3 危险调用前置 `guardrails/dangerous_call.py`（104 行）
`detect_dangerous_calls()`（:67）：危险动作词表（`patterns/dangerous_actions.json`，可外置覆盖 fail-fast）+ 契约白名单外 API + 形状层（`device[name]()`/`eval/fetch`，仅 code 场景）。合法 API 不误报。接入 `input_guard.check_input`（:28）命中按 `INJECTION`/`DANGEROUS_CALL` 短路，不进模型、不新增 ReasonCode。模型兜底刻意不实现。

### 5.4 真像素快照 `sandbox_runner/snapshot.py`（104 行）

### 5.5 会话修正 `sessions/revision.py`（183 行）


## 11. 已知边界（阅读时不必困惑）

- **M08 V3 未强制串进 `run()`**：入口 `validate_and_test` 已实现，但 loop 终态缺经校验的 spec/source_ref/manifest 三入参，待 M04/M07 结构化生成回路 + 真实模型（M08 §9 登记）。
- **无真实模型端点**：PlanLLM/Generator/Reviewer 生产 fail-fast、测试 mock；多任务真模型端到端验收登记环境阻断（M04/M07 缺口文档）。
- **reasoning SSE tail / 前端折叠**：kind=21 已入契约，实时 tail（`XREAD BLOCK`）与 `apps/web` 折叠组件未做（ADR-008 §10 S2/S3）。
- **ADR-010 S4**：真模型端点下的影子期阈值校准，依赖 M20，非实现缺失。
- **device-apis.json 不进 contracts drift 链**：独立数据文件，由 Python payload 注入沙箱。
- **S3 端点语义**：`post_message` 仅两类修正分支走新逻辑，多任务消歧（ADR-009）仍在原链路。
