## 0. 先建立整体认知

本轮解决的是 ADR-004 §3 遗留缺口（设备 API/续航/沙箱校验）与 ADR-010 的四块交付。三块判定 + 一块证据增强，**全部零模型**：

- 快照缺口（B2）：jsdom 无布局引擎只能出 DOM 序列化 html，补一个宿主机 Chrome 真像素渲染器。
- S1：模拟手机系统对 widget 的压制（限频/Doze/渲染风暴/重试风暴/长任务）。
- S2：把危险接口/高危 API/危险动作提前到进护栏拦截。
- S3：两类会话修正语义（违法输入撤销合并、任务中途改需求重跑）。

三块判定都遵循同一模式：**纯函数检测器 + 接线层**。检测器不写库、不发事件、不调模型；副作用集中在 `entry.py` / `server.py`。

## 1. 阶段 1 · 数据契约（先读，否则后面全是陌生常量）

### 1.1 `packages/contracts/device-apis.json`（27 行）—— 设备 API 单一事实来源
7 个受限 API（`getLocation` 30s / `getBattery` 60s / `getNetworkStatus` 15s / `sendNotification` 5 次每小时 / `scheduleRefresh` **30 分钟下限** / `storage.write` 10 次每秒 / `render.update`）+ 阈值（全量渲染 10/分钟、重试窗 3、ANR 10s、位图内存 `6*w*h`）+ 5 个危险类别。
**约束值来源**：Android 官方文档（AppWidget `updatePeriodMillis` ≥ 30min、广播 10s ANR、Glance 每小时 ≤1 次、RemoteViews 位图上限）。

### 1.2 `services/guardrails/patterns/dangerous_actions.json`（19 行）—— 危险动作词表
危险动作短语 + 撤销意图短语。可由 `WIDGETPILOT_DANGEROUS_LEXICON_PATH` 按类别整体覆盖，外置非法 fail-fast（同 ADR-005 敏感词库纪律）。危险**接口名**不在词表——来自上面的 device-apis.json 白名单。

### 1.3 新增 dataclass
- `DeviceCall` / `Violation` / `DeviceLimits`（`detector.py:35/46/56`）—— 调用序列、违规、限流常量。
- `DangerVerdict`（`dangerous_call.py:39`）—— 危险调用判定。
- `MergeResult` / `RevisionPhrases`（`revision.py:45/55`）—— 合并结果与词表。
- `EvidenceRefs.snapshot_png_ref`（`output_ports.py`）—— 末尾追加且默认 None，旧 6 位位置构造兼容。

## 2. 阶段 2 · 纯判定层（心脏，逐行读）

### 2.1 `services/orchestrator/device_sim/detector.py`（185 行）—— 五类违规检测
`detect_violations()`（:101）是唯一入口，输入调用序列、输出 `tuple[Violation]`：
- ①白名单外 API = `dangerous_api`；②最小间隔/每小时配额违反 = `high_frequency`；③全量渲染超阈 = `render_storm`；④限流后短窗重试 = `retry_storm`；⑤耗时 > ANR = `long_task`。
- `load_limits()`（:76）从 device-apis.json 读，缺失/非法即抛（fail-closed）。
- **只读、零副作用**：不修代码、不写库。重构建议随 `Violation.remediation` 文本返回。

### 2.2 `services/guardrails/dangerous_call.py`（103 行）—— 危险调用前置检测
`detect_dangerous_calls()`（:67）—— 词表层（危险动作短语）+ 白名单层（契约外 API）+ 形状层（`device[name]()` 动态构造、`eval/fetch` 等危险全局，仅 `source_kind="code"` 启用）。合法 API 名（白名单内）不误报。

### 2.3 `services/control_plane/sessions/revision.py`（182 行）—— 会话修正纯逻辑
- `detect_revocation_intent()`（:105）—— T2 是否表达撤销（子串匹配、零模型）。
- `strip_dangerous_segments()`（:118）—— 按句读切分，剥离命中违法词的整句，返回残余合法文本 + 命中词（供审计，不写违法原文）。
- `merge_revised_description()`（:145）—— 合并 T1 合法片段 + T2 意图；保留两轮原文。

### 2.4 `services/sandbox_runner/snapshot.py`（103 行）—— 真像素渲染端口
`SnapshotRendererPort`（:39）协议 + `ChromeSnapshotRenderer`（:47）真实实现。`render()`（:73）用 headless Chrome 静态渲染 html → png，缺 Chrome / 失败 / 非 png magic 均返回 None（降级，不伪造）。Windows 路径探测用 `C:/` 盘符（非 git-bash `/c/`）。

## 3. 阶段 3 · 接线层（副作用都在这里）

### 3.1 `infra/sandbox/runner.js`（408 行）—— 沙箱内设备 mock
`installDeviceMock()`（:123）在 `window.eval(compiled)` 前安装 `window.widgetDevice`：限流/Doze/配额返回结构化 `{ok, code}`；每次调用追加 `window.__deviceCalls`（`{api,t_ms,code,args,duration_ms}`），report 顶层输出 `device_calls`（正常/异常/fatal 三路径均输出，空时为 `[]`）。
**契约注入**：`loadDeviceContract(payload.device_contract)`（:92）优先用 Python 注入的契约（消除容器内读不到 json 的内嵌副本漂移）。

### 3.2 `services/sandbox_runner/entry.py`（504 行）—— 沙箱汇总门禁
- `run_sandbox()`：payload 注入 `device_contract`（:153-160）；`DEVICE_API_ASSERT` 阶段（:217）调 `_device_calls_safe`（:476）→ 违规转 `SANDBOX_TEST_FAILED`；png 渲染（:245-254）经 `SnapshotRendererPort` 注入。
- `validate_and_test()`（:303）：默认 `ChromeSnapshotRenderer()`（:349），无 Chrome 自动降级。
- 阶段序列：`OUTPUT_GUARD → CONTRACT_CHECK → COMPILE → RENDER → SIZE_ASSERT → RUNTIME_ASSERT → CAPABILITY_ASSERT → INTERACTION_ASSERT → DEVICE_API_ASSERT → EVIDENCE_WRITE → PASSED`。

### 3.3 `services/sandbox_runner/evidence.py`（83 行）—— 证据写入
`write_evidence()`（:17）写 `snapshot.html` + `snapshot.png`（png magic 校验，非真 png 不写）；`verify_evidence_refs()`（:64）覆盖 png，篡改即 False。可选项（html/png）缺失跳过，关键证据（log/report/cases/compiled）缺失仍 False。

### 3.4 `services/guardrails/input_guard.py`（98 行）
`check_input()`（:28）在注入/PII/敏感词之后、意图白名单之前插入危险调用检测（:60 附近），命中按 `INJECTION` 类型、`rule_id=DANGEROUS_CALL` 短路，不进模型、不新增 ReasonCode。

### 3.5 `services/control_plane/api/server.py`（925 行）—— 会话修正接线
`post_message()`：`AWAITING_INPUT` + 撤销意图 → 合并分支（:406-418）；`RUNNING/PAUSED` + 描述变化 → 重跑分支（:428-434，interrupt 幂等 + 旧任务 CANCELLED）；其余走原链路（`else`，ADR-009 消歧 + `submit_message`，零回归）。`submit_revision()`（`service.py:202`）落新 run_id，历史不删。

## 4. 一条主线贯穿（自检用）

```
用户描述 → check_input(注入/PII/敏感词/危险调用) → 校验链 → 模型生成 TSX
→ 沙箱 runner: window.widgetDevice mock 记录 device_calls → report
→ entry: DEVICE_API_ASSERT(detector 五类违规) → 任一违规 = SANDBOX_TEST_FAILED + 证据
→ 渲染: ChromeSnapshotRenderer → snapshot.png → MinIO(带 hash)
→ 用户改口/改需求 → server.post_message 两类修正分支 → revision.py 纯逻辑 → submit_revision
```

## 5. 不变量 / 风险点 → 代码位置速查

| 不变量 | 代码位置 |
|---|---|
| 契约单一事实来源 | `device-apis.json` → `entry.py:153` 注入 → `runner.js:92` 优先用 payload |
| 零设备调用零回归 | `runner.js` 输出 `device_calls=[]`；`detector` 空序列返回 `()` |
| 无 Chrome 不伪造 png | `snapshot.py:73` 返回 None → `evidence.py:38` 不写 png_ref |
| 危险调用不进模型 | `input_guard.py` check_input 命中 short_circuit=True |
| 合法 API 不误报 | `dangerous_call.py:_interface_names()` 白名单来自契约 |
| 合并不写违法原文 | `revision.py:118` 只返回剥离词；`server.py` 审计只写 hash + 词 |
| 改需求不删历史 | `service.py:submit_revision` + 旧任务 CANCELLED，checkpoint/审计/task_turn 保留 |
| 模型兜底不实现 | `dangerous_call.py` 模块 docstring：无端点 fail-fast 且不得单独放行 |

## 8. 已知边界（阅读时不必困惑）

- **S4 未做**：真模型端点下的影子期阈值校准（全量渲染阈值、重试窗的真机调优），依赖 M20，ADR-010 已登记——是环境依赖，不是实现缺失。
- **device-apis.json 不进 contracts drift 链**：作为独立数据文件，不参与 `pnpm contracts:check` 的四生成物比对（枚举/zod/openapi/python SDK），由 Python payload 注入沙箱。
- **S3 端点语义**：`post_message` 只在识别到撤销/改需求两类分支时走新逻辑；多任务消歧（ADR-009）仍在原链路，零回归。
