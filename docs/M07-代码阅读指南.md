## 0. 整体认知

M7 承载 X2（上下文管理）/ X3（记忆管理）/ X4（成本管理），主责 14 步链路的 ⑥⑦ 步。
它是**业务装配方**：M03 提供 `loop/decide/meter/checkpoint` 内核原语，M7 把"六槽位怎么装、四层记忆怎么学、
成本怎么落账、断点怎么接"这些业务规则接到内核上。D-5 零 Agent 框架仍然成立。

**四层记忆边界（禁止混存，ADR-002 D-9/D-14）**：

| 层 | 载体 | 生命周期 | 内容 |
|---|---|---|---|
| 工作记忆 | M04 `Run`/checkpoint/SSE | 会话内 | 当前 super-step、`clarification_answer` |
| 情节记忆 | PG `preference_event`（只追加、hash 链） | TTL 180 天失效不删行 | 何时/何会话/何种信号/学到什么 |
| 语义记忆 | PG `user_preference`（每字段证据化） | 长期、随版本更新 | palette / preferred_grids / preferred_widget_types |
| 程序记忆（v1.5 新增） | PG `user_procedure` | 长期、显式遗忘 | 采纳哪类 recipe 的计数（零 LLM、不写 prompt 前缀） |

**四类写入信号**：`explicit`(1.0，REST PUT) / `clarification`(0.8，澄清点选) /
`adopted_artifact`(0.3，采纳产物) —— 三类已在生产代码实装；
`correction`(0.7，规格/附件纠偏) 依赖 M08 事件，见 `docs/modules/M08-出护栏契约校验与沙箱测试域.md §9.0`。

## 4. 一条主线的调用链（带断点编号）

```
control-plane POST /sessions/{id}/messages
  → Redis 任务入队（user_id/session_id/run_id/description/grid...）
worker.process_one() → dispatcher.process_one()
  → _check_guardrail()  build_validator 闭包
      → validate_chain(preferred_grids = high_confidence_grids(preference_store.get(user_id)))   [B1]
      → ValidationResult（ok/tier/widget_type/intent_normalized/attachment_refs/evidence_ref）
  → Input(... 全字段 + context_user_id)                                                      [B2]
  → input_enricher(run_input)  注入 PreferenceInjectionAdapter / ProcedureHintAdapter
  → run(session, run, Input, deps, cost_sink=_cost_sink)
      → B2/B3 回注：spec.tier / spec.evidence / state.clarification_answer（从 SessionRow 读）
      → if catalog or has_data_ports: assemble(state, SlotConfig(四端口))                    [B8]
      → loop: decide → 模型（FakeModel/真实网关）→ meter.add → checkpoint
      → 终态 → cost_sink(state) → accrue → PgCostLedger.append（指纹含 preference_version）    [B7]
  → _write_back() 终态回写会话
澄清路径：POST /clarifications → answer_clarification（写 SessionRow.clarification_answer）
      → learn_from_clarification（偏好学习）→ 重入队 → B3 回注 State
采纳路径：preference_learning.learn_from_adopted_artifact（偏好 + 程序记忆）
      → 触发方 M09 安装事件（未落地，见 M09 §9.0）
```

B1–B8 逐条闭合证据见 `docs/modules/M07-生成编排与成本域.md §9.6`；本文不重复。

## 5. 数据模型速查

- `UserPreference`：`user_id` + `fields: dict[PreferenceField, FieldEvidence]` + `version`。
  `FieldEvidence` = value/source/weight/evidence_count/updated_at。
- `PreferenceEvent`：只追加；`decision`(ADD/UPDATE/DELETE/NOOP)、`superseded_at`/`revoked_at`（不删行）、
  `row_hash`（sha256 链）、`trace_id`，权限按 `user_id` 隔离。
- `UserProcedure`：`user_id`+`recipe_id` + `widget_type`/`adopt_count`/`last_adopted_at`/`version`。
- `CostEntry`：`run_id`(UNIQUE) / `session_id` / `user_id` / `model_tier` / 四维用量 / `repro_fingerprint`。
- `ReproInputs`：十字段（prompt_version + recipe_version + retrieval_snapshot + model + model_version +
  tier_rubric_version + temperature + seed + spec_version + preference_version）。

PG 表由迁移 `0010_m07_memory`（三表）与 `0011_cost_ledger` 建立，均有幂等守卫；DSN 经 `_sync_dsn()` 归一化。
