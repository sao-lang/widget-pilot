# M03 · agent_core 代码阅读指南

> 面向第一次接手 `packages/agent_core` 的开发者。目标：用最短路径建立骨架认知，
> 再按需要深入。本指南是阅读顺序建议，不新增任何设计决策；权威规格见
> `docs/modules/M03-手写Harness内核.md`，行为判据见 `tests/`。

---

## 0. 先建立整体认知

M03 是**库，不是服务**：无独立进程、无端口、不建表、不提供 REST。它是 D-5
「零 Agent 框架」定稿的载体，把框架黑盒里的不变量——状态迁移、幂等、恢复、
结构化校验、成本计量——显式化为可单测的代码。所有跨进程依赖（PG / Redis /
对象存储 / 向量库 / model gateway / OTel）都以 Protocol 注入，因此可以完全
脱离真实基础设施单测。

规模：`packages/agent_core/` 共 39 个 Python 文件、约 2000 行；测试 13 个文件、
约 1300 行。**不要按文件名字母序逐个读**，按下表 6 个阶段读。

```
阶段 1  数据模型       types.py / enums.py / errors.py / constants.py
   ↓
阶段 2  依赖边界       injection.py（7 Protocol + Deps）
   ↓
阶段 3  核心心脏  ★    loop/decide.py → loop/run.py
   ↓
阶段 4  崩溃恢复三件套  state/checkpoint / lease / idempotency
   ↓
阶段 5  八大支撑模块    structured / tools / guardrails / context / budget / events / model / eval
   ↓
阶段 6  测试即文档      conftest.py → test_decide → test_run → test_e2e
```

## 2. 阶段 2 · 依赖边界（建议通读，111 行）

`packages/agent_core/injection.py`

## 3. 阶段 3 · 核心心脏（全库最重要，逐行读）

这是整个 harness 的灵魂，花最多时间在这里。

### 3.1 `loop/decide.py`（88 行）—— 纯函数判定树

`decide(state) -> Decision` 是**唯一的状态迁移入口**。铁律：只读 State 的
确定性字段，不调模型、不落盘、不发事件、不读时钟。同一 State 必得同一 Decision。

9 个分支的**固定优先级**（从上往下判定，读懂顺序就读懂了状态机）：

| 顺序 | 条件 | 产出 kind |
|---|---|---|
| 0 | `terminal is not None` | `FAILED`（防御性） |
| 1 | `phase == AWAITING_INPUT` 且有答案 / 无答案 | `RESUME_FROM_CLARIFICATION` / `AWAIT_INPUT` |
| 2 | `iteration >= MAX_ITER` | `FAILED` + `RETRY_EXHAUSTED` |
| 3 | `__signal == REPAIR`，未超 `MAX_REPAIR` / 超限 | `REPAIR` / `HANDOFF` |
| 4 | `__signal == ASK_USER`，未超 `MAX_CLARIFY` / 超限 | `ASK_USER` / `HANDOFF`+`CLARIFICATION_LIMIT` |
| 5 | `__signal == AWAIT_INPUT` | `AWAIT_INPUT` |
| 6 | `__signal == DONE / FAILED / HANDOFF` | 对应终态 |
| 7 | `__signal == CALL_TOOL` | `CALL_TOOL` |
| 8 | 默认 | `CALL_MODEL`（唯一调模型分支） |

关键设计：`spec["__signal"]` 等 `__` 前缀字段是**保留键**，承载「上一步已写入的
可信结论」，由 `apply_model_output` / `repair.feedback` / 澄清端点写入，`decide`
只读不产生。这样模型这个「唯一不可信变量」被隔离在 `run.py` 的 `CALL_MODEL` 分支。

### 3.2 `loop/run.py`（178 行）—— 显式 while 主循环

对照文档 §11.3 的 `run()` 代码读。核心超步（super-step）：

```
装载 checkpoint（无则 State.initial） → 抢租约 → while:
    decide → 分支动作 → 同步落盘 → 发事件 → budget.check → lease.heartbeat
finally: 释放租约
```

**4 个必看细节**：

1. **模型只在 `CALL_MODEL` 分支调用**（T3：`model.complete` 在其它分支调用数必须为 0）。
2. **挂起态退出循环**：while 条件含 `phase != AWAITING_INPUT`，挂起不占计算资源。
3. **落盘统一走 `state/checkpoint.py:save_checkpoint`**：`_persist()` 用
   `rev = max(state.rev, latest_rev+1)` 保证恢复时不撞主键 `(run_id, rev)`。
4. **每个事件独立递增 seq**（I8：连续、无重复、无倒序）。

辅助函数：`apply_model_output`（把不可信输出转成可信状态迁移）、`apply_tool_result`。

## 4. 阶段 4 · 崩溃恢复三件套

| 文件 | 行数 | 读什么 |
|---|---|---|
| `state/checkpoint.py` | 65 | `save_checkpoint` 的 hash 链：`row[i].prev_hash = sha256(prev_row.prev_hash + hash(state_bytes))`；`chain_valid` 从对象存储回读重算每一环 |
| `state/lease.py` | 29 | 抢锁/心跳/释放/扫描；同时提供对象式（run 用）与模块级函数式（恢复扫描用）两种调用形态 |
| `state/idempotency.py` | 23 | `idem_key = session_id + step + payload_hash`，命中直接复用 `result_ref`，不重复执行副作用 |

**关注点**：hash 链定义是单一真相（run 不自己算 hash）；`scan_expired` 只扫
`lease_until < now AND terminal IS NULL` 的 run（终态不再被恢复）。这对应
§11.4 的「手写 durable execution」。

2. worker 在 checkpoint 处被杀、用户跨天回来，状态怎么恢复、副作用怎么不重复？
