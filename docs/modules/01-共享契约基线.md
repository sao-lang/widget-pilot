## 1. 核心实体与字段（【原文】§4.1）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `User` | `id`, `email`, `password_hash`, `role`(`user`/`curator`), `share_enabled`, `quota`, `created_at` | 账号与配额归属 |
| `Session` | `id`, `user_id`, `title`, `state`, `grid`(可空), `grid_source`, `clarify_count`, `created_at`, `updated_at`, `last_seq` | 会话主记录，`state` 见 §3；`grid` 可空（v1.3 D-6：可选预填 + 缺省询问），进入生成回路前必已确定 |

| `WidgetBundle` | `id`, `user_id`, `session_id`, `spec_ref`, `source_ref`, `compiled_ref`, `manifest`, `static_check`, `sandbox_test`, `state`, `hash`, `versions[]` | 产物索引，大对象在对象存储 |
| `CorpusItem` | `id`, `bundle_id`, `owner_user_id`(脱敏), `grid`, `widget_type`, `spec_version`, `recipe_version`, `quality_score`, `toxicity_check`, `revoked_at` | 公共语料条目，可撤回 |
| `AuditEvent` | `seq`, `user_id`, `session_id`, `actor`, `action`, `decision`, `payload`, `trace_id`, `prev_hash` | 只追加，hash 链防篡改 |
| `EvalCase` | `id`, `source`(`history`/`adversarial`/`expert`), `input_ref`, `expected`, `rubric`, `result` | 评测集 |

**字段归属原则（【原文】）**：逐轮过程数据（spec 增量、代码 patch、护栏命中、回边、成本）放事件流与 `Run`，**不塞进 `Session` 主记录**；大对象一律存对象存储引用。

## 2. 六种控件规格（【原文】§1.5）

`grid` 是生成前必须确定的**一等约束**，但获取方式为 **可选预填 + 缺省询问，系统不推断**（v1.3，ADR-001 D-6）：前端选择器可跳过；描述含明确规格线索由规则词表确定性解析（`grid_source="explicit_text"`）；皆无则 `AWAITING_INPUT` + `SPEC_MISSING` 主动询问用户。规格同时约束生成协议的 `layout_slots`、静态校验的尺寸断言、前端卡片渲染的真实比例。

| `grid` | 网格 | 前端像素（`cell=80px`） | 典型可用信息密度 | 约束示例 |
|---|---|---|---|---|
| `2x1` | 2 列 1 行 | 160×80 | 单行文本 / 数字 | 放不下月视图日历，触发规格冲突提示 |
| `1x2` | 1 列 2 行 | 80×160 | 竖排短信息 | 不适合宽表格 |
| `2x2` | 2×2 | 160×160 | 日期 + 简短事项 | 中等 |
| `2x4` | 2 列 4 行 | 160×320 | 列表型（待办 / 日程） | 可滚动区域需声明 |
| `4x2` | 4 列 2 行 | 320×160 | 横向多指标 | 横向布局优先 |
| `4x4` | 4×4 | 320×320 | 日历月视图 / 复杂面板 | 信息密度上限最高 |

## 3. 状态与枚举（【原文】§4.2，前后端共用同一枚举）

```ts
type GridSpec = "2x2" | "2x4" | "4x2" | "4x4" | "2x1" | "1x2";
type WidgetType = "calendar" | "clock" | "alarm" | "task" | "custom";
type AttachmentRole = "visual_reference" | "content_extraction" | "data_source" | "style_reference";
type Capability = "date" | "timer" | "local_storage" | "static_data" | "theme" | "locale";
type ModelTier = "cheap" | "standard" | "frontier";

type SessionState =
  | "DRAFT" | "RUNNING" | "PAUSED" | "AWAITING_INPUT" | "VALIDATING"
  | "COMPLETED" | "FAILED" | "CANCELLED";

type BundleState = "GENERATED" | "INSTALLED" | "DELETED";

type ReasonCode =
  | "INPUT_INVALID" | "INTENT_OUT_OF_SCOPE" | "GUARD_INPUT_HIT" | "GUARD_OUTPUT_HIT"
  | "SPEC_CONFLICT" | "SPEC_MISSING" | "CAPABILITY_DENIED" | "CONTRACT_MISMATCH" | "COMPILE_FAILED"
  | "SANDBOX_TEST_FAILED" | "RETRY_EXHAUSTED" | "BUDGET_EXHAUSTED"
  | "SANDBOX_UNAVAILABLE" | "HUMAN_REQUIRED" | "MODEL_ERROR"
  | "CLARIFICATION_REQUIRED" | "CLARIFICATION_LIMIT";   // v1.3 新增（ADR-001），需 M02 收敛入 openapi.yaml
```

### 3.1 会话状态机（【原文】§1.4）

```
DRAFT → RUNNING ⇄ PAUSED（用户停止 / 断点）
      → AWAITING_INPUT（描述不足 / 附件 role 歧义 / 规格冲突 / 规格缺失询问 SPEC_MISSING / 模型执行中澄清 CLARIFICATION_REQUIRED）
      → VALIDATING（出护栏 + 契约校验 + 沙箱测试）
      → COMPLETED（产物就绪，进入控件墙）
旁路：FAILED（带原因码 + 证据引用） / CANCELLED
```

**任何旁路状态必须带原因码 + 证据引用**，前端不得只显示「失败」。

### 3.2 产物状态机（【原文】§1.4）

`GENERATED → INSTALLED → DELETED`。安装与删除是 App 内的状态操作，**不触发真实装机**；删除不可逆，需二次确认 + 审计，不做乐观更新。

### 3.3 状态流转表（【契约约定】，供各模块 §5.2 引用）

| 触发 | 前态 | 后态 | 副作用 | 事件 `kind` |
|---|---|---|---|---|
| 新建会话 | — | `DRAFT` | 写 `Session`，分配 `session_id` | `run` |
| 提交描述 | `DRAFT` | `RUNNING` | 开新 `Run`，分配 `runId`，抢租约 | `run` |
| 描述不足 / role 歧义 / 规格冲突 / 规格缺失 / 模型请求澄清 | `RUNNING` | `AWAITING_INPUT` | 写 checkpoint（含 `clarify_count`）、释放租约；规格缺失/冲突推 `notice`，模型澄清推 `ask_user` | `notice` / `ask_user` |
| 用户回答澄清（`POST /clarifications`） | `AWAITING_INPUT` | `RUNNING` | 抢租约、答案入 `clarification_answer` 槽位、`clarify_count += 1`、从节点顶部重执行 | `run` |
| 用户停止 | `RUNNING` | `PAUSED` | 写 checkpoint、释放租约、取消上游模型调用、账单同步停止 | `interrupted` |
| 用户继续 | `PAUSED` | `RUNNING` | 按 `runId + seq` 恢复 | `run` |
| 生成完成，进入校验 | `RUNNING` | `VALIDATING` | 触发出护栏 / 契约校验 / 沙箱 | `validation`、`sandbox` |
| 校验失败且回边未超限 | `VALIDATING` | `RUNNING` | `REPAIR` 回边，`repair_count += 1` | `notice` |
| 全部校验通过 | `VALIDATING` | `COMPLETED` | 生成 `WidgetBundle`，写审计 | `artifact`、`done` |
| 回边 > 2 / 预算触顶 / 沙箱不可用 | `VALIDATING` | `FAILED` | 原因码 + 证据引用 + 保留部分产物 | `error` |
| 用户取消 | 任意非终态 | `CANCELLED` | 立即释放沙箱、释放租约 | `interrupted` |

## 4. 三份核心协议（【原文】§4.3）

> **贯穿约束**：同一份 `manifest` 贯穿四处 —— 生成侧按 spec 产码 → 静态校验比对能力声明 → 沙箱测试按声明放行 → 运行时 bridge 按声明放行 → 评测按声明出判据。

### 4.1 生成协议 `WidgetSpec`

```ts
type WidgetSpec = {
  spec_version: string;              // 版本化，索引与 manifest 均绑定
  widget_id: string;
  grid: GridSpec;                    // 可选预填 + 缺省询问补全，系统不推断（v1.3 ADR-001 D-6）；生成回路入口处必非空
  widget_type: WidgetType;
  intent: string;                    // 归一化后的描述
  attachments: {
    attachment_id: string;
    role: AttachmentRole;            // 由描述决定，可在前端纠偏
    insight_ref: string;             // AttachmentInsight 对象引用
  }[];
  layout_slots: { slot: string; content: string }[];   // 受 grid 信息密度约束
  capabilities: Capability[];        // 声明式能力，渲染侧按此放行
  data_contract: {
    sources: ("time" | "local_storage" | "static")[];
    storage_namespace: string;       // 按 user + widget 隔离
  };
  style: { palette?: string[]; radius?: number; font_scale?: number };
  constraints: { forbidden: string[]; max_elements: number };
  language: "tsx";
  react_version: string;
  import_allowlist: ["react", "@widget/bridge"];
  export_contract: { default: "Widget" };
  props_contract: ["grid", "theme", "locale", "tick", "data"];
};
```

生成侧**先产出可校验的 `WidgetSpec`，再据此生成代码**；规格冲突（如 `2x1` + 月视图）在 spec 层即被拒绝并提示用户改选。复杂嵌套 structured output 在规模下易碎，因此采用「prompt 生成 → 校验 → 自纠正」而非硬塞 constrained decoding。

### 4.2 产物协议 `WidgetBundle`

```ts
type WidgetBundle = {
  bundle_id: string;
  user_id: string;
  session_id: string;
  spec: WidgetSpec;
  source: { path: "widget.tsx"; content_ref: string; language: "tsx" };
  compiled: { content_ref: string; hash: string };
  manifest: {
    spec_version: string;
    spec_hash: string;
    grid: GridSpec;
    widget_type: WidgetType;
    capabilities: Capability[];      // 与 spec 一致，静态校验比对
    import_allowlist: string[];
    exports: { default: "Widget" };
    props: string[];
    recipe_version: string;          // 所用规程版本
    retrieval_snapshot: string;      // 所用检索快照与引用
    model: string; prompt_version: string; model_tier: ModelTier;
  };
  static_check: { passed: boolean; violations: string[] };
  sandbox_test: {
    passed: boolean;
    cases: { name: string; passed: boolean; detail_ref: string }[];
    log_ref: string; snapshot_ref?: string;
  };
  state: BundleState;
  hash: string;                      // 整包摘要，防篡改
  created_at: string;
};
```

### 4.3 渲染协议 `WidgetRuntime`

```ts
type WidgetRuntime = {
  card: { grid: GridSpec; px: { w: number; h: number } };  // 真实比例
  iframe: {
    sandbox: ["allow-scripts"];       // 不含 allow-same-origin / top-navigation / forms / popups
    csp: string;                      // 禁外联脚本、禁 eval、禁网络
    srcdoc_ref: string;               // 指向 compiled 产物
  };
  bridge_messages: [
    "widget:ready", "widget:resize", "widget:error",
    "host:theme", "host:locale", "host:tick", "host:data"
  ];                                  // 窄协议，非任意 JSON-RPC
  capability_bridge: Capability[];    // = manifest.capabilities ∩ 白名单；未声明调用拒绝并上报
  limits: { render_timeout_ms: number; max_message_rate: number };
};
```

宿主 ↔ 控件**只走上述消息**；时间统一由 `host:tick` 提供，本地存储按 `storage_namespace` 隔离；控件不得 `fetch`、不得访问父页面 DOM、不得调用系统 API。

### 4.4 附件洞察 `AttachmentInsight`（【原文】§5 D2）

### 5.1 统一响应格式（【原文】§4.4 / §6.9）

```ts
type ApiResponse<T> = {
  code: string;            // 成功为 "OK"；失败为 ReasonCode，与枚举对齐
  message: string;
  traceId: string;
  retryable: boolean;
  evidenceRef?: string;    // 失败时指向证据引用
  data?: T;                // 【契约约定】成功载荷
};
```

`code` 与 `ReasonCode` 对齐。错误响应统一映射，前端按 `code` 展示具体原因与「从断点继续 / 改描述重试」入口，**不显示裸「失败」**。

### 5.2 关键请求体（【契约约定】，最终以 `openapi.yaml` 为准）

```ts
// POST /api/sessions（v1.3：grid 可选，缺省由语义层询问补全）
type CreateSessionReq = { title?: string; grid?: GridSpec };

// POST /api/sessions/{id}/messages（v1.3：grid 可选）
type PostMessageReq = {
  description: string;
  grid?: GridSpec;
  attachment_ids: string[];
};

// POST /api/sessions/{id}/clarifications（v1.3 新增，ADR-001 D-7）
type PostClarificationReq = { question_id: string; answer: string };
// 服务端：校验 question 归属与 clarify_count 上限 → 答案写入 clarification_answer 槽位 → 会话回 RUNNING

// PUT /api/users/me/preferences（v1.4 新增，ADR-002 D-10）
type PutPreferenceReq = Partial<Pick<UserPreference,
  "palette" | "preferred_grids" | "preferred_widget_types"
>>;  // 显式写入，source="explicit" 权重 1.0；低权重信号不可覆盖
// 响应：{ code:"OK", data:{ preference, version, decision:"ADD"|"UPDATE"|"NOOP" } }

// DELETE /api/users/me/preferences（v1.4 支持 fields，ADR-002 D-13）
type DeletePreferenceReq = { fields?: ("palette" | "preferred_grids" | "preferred_widget_types")[] };
// 省略 fields = 全清；字段置空、version+1、证据标 revoked_at（不删行）

// POST /api/attachments（multipart/form-data）
// 字段：file, session_id；服务端返回 { attachment_id, kind, mime, size, hash }

// PATCH /api/sessions/{id}/attachment-roles
type PatchRolesReq = {
  roles: { attachment_id: string; role: AttachmentRole }[];
};  // 触发从该步重跑

// GET /api/sessions/{id}/events
// Query: runId, Last-Event-ID（也可走 header）；ticket 由 BFF 签发，短期有效
```

### 5.3 HTTP 状态码映射（【契约约定】）

| HTTP | 场景 | `code` 示例 |
|---|---|---|
| `200` | 成功 | `OK` |
| `202` | 异步任务已受理（生成提交、interrupt/resume 已排队） | `OK` |
| `400` | 输入不合法 / 规格冲突 | `INPUT_INVALID`、`SPEC_CONFLICT` |
| `401` | 未登录 / JWT 失效 | `UNAUTHORIZED`（【推导·需评审】：原文 `ReasonCode` 未含鉴权码，可复用 `INPUT_INVALID` 或扩充枚举，需 M02 定稿） |
| `403` | 越权访问他人会话 / 包 / 语料接口 | `FORBIDDEN`（同上，需 M02 定稿） |
| `409` | 状态冲突（对终态会话重复 resume、重复安装） | `CONTRACT_MISMATCH`（或扩充） |
| `422` | 语义校验 / 护栏命中 | `GUARD_INPUT_HIT`、`INTENT_OUT_OF_SCOPE` |
| `429` | 限流 / 配额触顶 | `BUDGET_EXHAUSTED` |
| `503` | 沙箱不可用 / 模型不可用降级 | `SANDBOX_UNAVAILABLE`、`MODEL_ERROR` |
| `5xx` | 内部错误 | `MODEL_ERROR` / `HUMAN_REQUIRED` |

> **注意**：`401/403/409` 对应的业务码原文 `ReasonCode` 未显式列出。M02 在生成 `enums` 时必须明确是「扩充枚举」还是「复用现有码」，并在 CI 校验中固定，不允许前后端各自解释。

### 5.4 权限模型（【原文】§1.3 / §6.9）

- JWT + 邮箱密码，两个角色：`user`（普通用户）、`curator`（语料审核员）；不接 OAuth（D-3）。
- **权限裁剪在服务端完成**；前端隐藏按钮只作为体验优化。
- 服务端按 `user_id` 对**每个 REST 请求与每条 SSE 事件**做权限校验。
- 平台管理员视图（评测、运行监控）在原文 §1.3 出现，但角色枚举只有两角色；【推导·需评审】：管理员能力建议由 `curator` 扩展或单独配置，`User.role` 枚举是否扩充需 M02/M04 定稿。

## 6. 实时事件协议（【原文】§4.5）

> **计数口径（v1.3 已修订）**：`AgentEventKind` 原文 §4.5 定稿 **17** 个字面量；v1.3（ADR-001 D-7）经用户确认扩充为 **18** 种 —— 新增 `ask_user`（执行中澄清问题）。该变更由 M02 走契约变更收敛入 `openapi.yaml` 并触发 M10 回归门禁；前端 reducer 对未知 `kind` 仍须忽略而非报错。

```ts
type AgentEventKind =
  | "run" | "plan" | "spec" | "attachment" | "skill" | "routing"
  | "code" | "guard" | "validation" | "sandbox" | "artifact"
  | "cost" | "checkpoint" | "interrupted" | "notice" | "error" | "done"
  | "ask_user";   // v1.3 新增

type AgentEvent = {
  seq: number;                 // 每会话单调递增
  sessionId: string;
  runId: string;               // 重连与跨天恢复的锚点
  ts: string;
  kind: AgentEventKind;
  phase: SessionState;
  payload: unknown;            // 按 kind 用 discriminated union 收窄
  traceId: string;
};
```

### 6.1 分通道约定（【原文】§4.5 / §6.4）

| 通道 | payload 形态 | 消费方 |
|---|---|---|
| `plan` | 结论式短句（不是思维链） | M15 折叠步骤条 |
| `spec` | 逐步逼近完整的 `WidgetSpec` JSON（partial） | M15 容错解析 + 骨架占位 → M14 规格预览卡 |
| `attachment` | `role` 判定 + `insight_ref` | M14 附件卡与纠偏入口 |
| `skill` / `routing` | 规程 id、模型档位、阈值命中 | M14 链路账小标签 |
| `code` | 行级增量 patch `{ from_line, to_line, text }` | M15 增量更新编辑器 |
| `guard` / `validation` / `sandbox` | 通过项、命中项、失败原因码 | M15/M14 分步清单，失败可展开证据 |
| `artifact` | `bundle_id` + 预览引用 | M14 原子替换占位卡 → M16 热更新 |
| `ask_user` | `{ question_id, question, options?, allow_text, clarify_count, clarify_limit }`（v1.3） | M14 澄清问题卡 → `POST /clarifications` 回答 |
| `cost` / `checkpoint` / `interrupted` / `notice` / `error` / `done` | 状态与账目 | M14 状态条 / 链路账；M17 状态迁移 |

### 6.2 可靠性与中断语义（【原文】§4.5）

- **可靠性**：`Last-Event-ID` 续传 + 服务端保留最近 N 条，超窗先拉快照；心跳保活；显式 `done` / `error`（无 `done` 视为截断）；事件按 `seq` 在前端 reducer 去重与乱序丢弃。
- **中断语义**：`interrupt` **不是关闭连接** —— 服务端写 checkpoint，流上推 `interrupted`，UI 切为「已暂停 · 从 XX 继续」；重连按 `runId + seq` 恢复。
- **向前兼容**：前端 reducer 对未知 `kind` **必须忽略而非报错**。
- **服务端**：禁用缓冲（`X-Accel-Buffering: no`）；错误作为流事件，不是静默断连。

## 7. ReasonCode 全表与失败去向（【原文】§4.2 + §10.1）

| `ReasonCode` | 触发控制点 | 典型失败去向 | 必须留存的证据 |
|---|---|---|---|
| `INPUT_INVALID` | 传输层 / 语义层校验 | 拒绝或 `AWAITING_INPUT` | 输入快照 + 校验日志 |
| `INTENT_OUT_OF_SCOPE` | 意图白名单 | 拒绝，不进模型 | 路由记录 + 原文引用 |
| `GUARD_INPUT_HIT` | 进 LLM 护栏 | 不进模型 | 命中类型 + 判据 + 原文引用 |
| `GUARD_OUTPUT_HIT` | 出 LLM 护栏 | 自纠正回边（≤2） | 命中与修正记录 |
| `SPEC_CONFLICT` | 规格校验 / spec 层 | 提示改选规格 | spec 快照 + 冲突项 |
| `SPEC_MISSING` | 语义层规格获取（v1.3） | `AWAITING_INPUT` 询问用户（`notice` 带 `suggest_grid`） | 描述快照 + 解析记录 |
| `CLARIFICATION_REQUIRED` | 模型执行中澄清（v1.3） | `AWAITING_INPUT`（`ask_user` 事件），回答后继续 | 问题 + 上下文快照 |
| `CLARIFICATION_LIMIT` | 询问次数 > 2（v1.3） | `HANDOFF` 转人工 + 保留部分产物 | 逐次问答记录 |
| `CAPABILITY_DENIED` | 能力白名单 / bridge | 回边或运行时拒绝上报 | 能力名 + manifest 声明 |
| `CONTRACT_MISMATCH` | 契约校验 | 不进沙箱 | 校验报告（spec/manifest/代码三方差异） |
| `COMPILE_FAILED` | TSX 编译 | 回边 | 编译日志 |
| `SANDBOX_TEST_FAILED` | 沙箱断言 | 回边 / 超限转人工 | 测试用例 + 日志 + 快照 |
| `RETRY_EXHAUSTED` | 回边 > 2 | `HANDOFF` 转人工 | 逐次失败原因 |
| `BUDGET_EXHAUSTED` | 四维预算触顶 | 确定性中断 | 成本账 + 触发维度 |
| `SANDBOX_UNAVAILABLE` | 沙箱启动失败 | 降级为静态校验 + 只读诊断（**绝不跳过校验直接交付**） | 降级记录 |
| `HUMAN_REQUIRED` | 超限 / 检索无结果 / 疑难 | 转人工 | 部分产物 + 原因码 + 证据引用 |
| `MODEL_ERROR` | 模型 429/5xx / 解析失败 | 基础设施重试（有上限）或降级 | 供应商响应 + 重试次数 |

## 8. 前后端职责划分（【原文】§7.3）

| 功能 | 前端主导 | 后端主导 | 共担 |
|---|---|---|---|
| 账号与权限 | 登录表单、角色视图裁剪 | JWT 签发、`user_id` 隔离、鉴权判定 | 账号契约 |
| 会话与状态 | 状态可视化、断点入口 | 手写状态机、checkpoint、租约续跑 | 状态枚举契约 |
| 流式事件 | 分通道渲染、reducer、回放、背压 | `seq` 生成、持久窗口、扇出、心跳 | **事件 schema** |
| 规格与附件 role | 选择器、纠偏交互 | 合法性校验、role 判定与处理 | 枚举契约 |
| 生成与校验 | 过程可视化、错误原因码展示 | 双向护栏、契约校验、沙箱测试 | 协议 schema |
| 产物与预览 | 卡片网格、iframe 渲染、包管理 | 产物生成、CSP、bridge 放行、版本 | **渲染协议** |
| 评测与指标 | 分布图、门禁结果 | 评测执行、统计、告警 | 指标定义 |

**策略、隔离、门禁统一在服务端裁决**；前端负责事件消费、可回放状态、纠偏交互与可审计的操作入口。

## 10. 术语表（【原文】附录 A，完整版）

| 术语 | 含义 |
|---|---|
| `WidgetSpec` | 生成协议：可校验的中间契约，含规格、附件 role、能力声明与数据约束 |
| `WidgetBundle` | 产物协议：TSX 源码 + 编译产物 + manifest + 校验与沙箱结果 + hash |
| `WidgetRuntime` | 渲染协议：iframe sandbox / CSP / 窄 postMessage / 能力 bridge |
| `AttachmentRole` | 附件用途（视觉参考 / 内容提取 / 数据源 / 风格参考），由用户描述决定 |
| `Capability` | 控件可使用的 webview 能力白名单：时间、定时器、受限存储、静态数据、主题、语言 |
| `bridge` | 宿主与 iframe 之间唯一允许的能力通道，按 manifest 声明放行 |
| `role 纠偏` | 用户在流式规格卡上改正附件用途并从该步重跑 |
| `runId` / `seq` | 任务执行标识与每会话单调递增事件号，用于重连与跨天恢复 |
| `checkpoint` | 只存结论与引用的状态快照，大对象放对象存储 |
| `自纠正回边` | 生成/校验失败后回到生成回路修正（≤2 次），不是基础设施重试 |
| `入库门禁` | 脱敏 / 质量筛选 / 投毒防护 / 归属与可撤回，产物进公共语料前必过 |
| `公共语料` | 跨用户共享的脱敏 spec + 代码 + 过程摘要，不含私有数据 |
| `一次生成通过率` | 无自纠正直接通过全部校验的任务占比，主质量指标 |
| `失败模式 rubric` | 按严重度加权的评测分类，替代单一「成功率」 |
| `event-sourced reducer` | 前端 `AgentEvent[] → SessionView` 纯函数，支撑回放与时间线 |
| `partial JSON` | 流式渐进解析未闭合 JSON，仅在 final 做严格校验 |
| `agent loop` | 手写显式状态机 while，模型只在 `CALL_MODEL` 分支出现 |
| `decide()` | 纯函数确定性状态迁移，不调模型；harness 可断言的核心 |
| `lease` | checkpoint 租约 + 心跳，用于崩溃后原子抢租约续跑 |
