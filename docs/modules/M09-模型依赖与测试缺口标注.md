## 2. 因缺真实模型/上游导致无法端到端走通的功能

| # | 功能 | 为什么走不通 | 真测所需条件 |
|---|---|---|---|
| M9-1 | 真实「自然语言描述→模型生成 WidgetSpec + TSX→落对象存储」 | M09 成包输入 `spec`/`source_ref` 由上游 M07 产出；当前无 `MODEL_ENDPOINT/MODEL_API_KEY/MODEL_NAME`，M07 生产启动即 fail-fast（`deps.py:268-272`） | 配置真实模型端点/key/模型名；M07 生成回路产出可渲染 TSX 并落 `code/{session}/{run}/widget.tsx` |
| M9-2 | M08 强制门禁串进 `run()` 后的真实成包链路 | `dispatcher.py:450-455` TODO：DONE 终态仍读模型自报 `bundle_ref`（`loop/run.py:376`），未强制调 `validate_and_test`；真实产物走不到 `BundleService.assemble()` | M08 入口已就绪，需在 dispatcher DONE 前插入 `validate_and_test` 并以 passed 为完成前提（M08 §9.5 缺口 1） |
| M9-3 | `bundle_ref` 指向真实产物（非模型自报字符串） | 迁移 0017 已让 `bundle_ref` 落 SessionRow，但值仍是模型自报；M09 成包产生真实 `bundle_id` 后需回灌 | M9-2 闭合后，成包真实 `bundle_id` 回写会话；否则 COMPLETED 会话的 bundle_ref 不可信 |
| M9-4 | 浏览器真实 iframe 渲染（CSP 拦截 / widget:ready/error 上报） | M09 只下发 WidgetRuntime 协议，真实 DOM 装配归 M16；无真实模型产物可渲染 | 真实模型产物 + M16 前端装配 + headless 浏览器 E2E（设计 §8.4） |

> 本轮验证策略：M09 用 `ValidateResult` 真数据结构 + 内存桩做接线测试（证明收纳/协议/状态机正确），
> 模型质量与端到端产物能力**不在本轮验收范围**，登记为上述 M9-1~M9-4 缺口。

## 4. 真测所需条件汇总（补齐后可达成的端到端验收）

1. **模型**：`MODEL_ENDPOINT` / `MODEL_API_KEY` / `MODEL_NAME`（M07 fail-fast 门槛）；
2. **上游生成**：M07 结构化生成回路产出 `WidgetSpec` + TSX 并落对象存储；
3. **M08 门禁**：`validate_and_test` 串进 dispatcher DONE 前，以 passed 为完成前提；
4. **前端**：M16 卡片墙 iframe 装配 + M15 reasoning 折叠；
5. **真实环境**：podman run 起 PG/Redis/MinIO（`podman compose` 暂不可用），headless 浏览器 E2E。

> 上述五项任一缺失，端到端产物能力都不可宣称已验收；M09 的单测全绿仅证明本模块内部正确。
