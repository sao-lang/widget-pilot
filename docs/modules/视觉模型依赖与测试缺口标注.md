# 视觉模型依赖与测试缺口标注（ADR-014 视觉工具组：接线完整，识别质量未验收）

> **生成日期**：2026-11-25　|　**关联**：`docs/adr/ADR-014-多媒体处理工具集与渐进披露接入.md`（v1.3，设计权威 §15.2）、`docs/modules/M05-附件处理域.md`（附件原文红线）、`docs/modules/M07-模型依赖与测试缺口标注.md`（姊妹篇，编排域模型缺口）、`docs/modules/M20-LLMProvider模型接入与切换.md`（端点配置）
>
> **目的**：ADR-014 v1.3 已把视觉模型调用封装成 6 个 tool（`tool.vision.*`）并接进 ADR-003 渐进披露。当前环境**无真实视觉端点 / key / 权重**，生产路径有**完整真实接线**（不是空壳、不是 fake），本机用 mock gateway 验证接线与降级。本文件逐项标注"哪些因此无法真测、真测所需条件是什么"，并将**非模型缺口单列**（§3），避免把 mock 全绿误读成"视觉能力已验收"。
>
> **纪律**：**接线正确 ≠ 模型质量达标**。行号逐字引自当前源码，未实测处标注"待确认"，不编造。

## 0. 一句话结论

| 维度 | 状态 | 证据 |
|---|---|---|
| 生产代码有真实视觉模型接线 | ✅ 有，逐跳完整 | `capabilities.py:733-745`（`tool.vision.compare` 等注册）→ `vision_tools.py:102-194`（6 个工具）→ `vision.py:46-83`（`ask_vision`）→ `Message(image_ref)`（`types.py:598,602-611`）→ `provider.py:81-85`（httpx.post 真实 HTTP） |
| 一组工具共享一个网关，无第二套 VisionPort | ✅ 是 | `vision.py:46` `ask_vision` 复用 `ModelGateway`；`understand_image` 改为薄封装（`vision.py:85-95`） |
| 缺配置时行为 | ✅ fail-fast | `deps.py:270-275`：缺 `MODEL_ENDPOINT/MODEL_API_KEY/MODEL_NAME` 即抛 `RuntimeError`，拒绝静默降级 fake |
| 本机测试（mock gateway + 真实 PG/Redis） | ✅ **756 passed / 10 skipped**（2026-11-25 实测） | `pytest -q` 退出 0；`test_m05_vision_tools.py` 9 项（降级/旧接口兼容/bbox 过滤/标签白名单/compare 拼图/端到端 handler） |
| 输出安全校验（纯代码，不依赖模型） | ✅ 已真测 | bbox 真值校验（`vision_tools.py:39-52`）、标签白名单（`:155-171`）、data URL 缩略图（`:27-37`）、降级不造假——均由 mock 测试覆盖 |
| **依赖真实视觉推理质量的功能** | ❌ **本机无法真测**（无端点/key/权重/标注集） | 详见 §2，共 6 项，对应 6 个工具 |
| **非模型缺口**（真实模型之外的工具链/契约） | 见 §3，单列不混算 | 像素级分割、多模态结果回灌、附件洞察槽注入 |

> 关键区分：**"工具封装/降级/校验是否正确"用 mock 真测；"视觉识别是否准确"因缺端点测不了**。mock 全绿只证明消息封装、输出解析、安全过滤正确，**不证明** bbox 定位准、OCR 识别准、分类对、描述靠谱。

## 1. 真实视觉模型接线在哪（生产路径，逐跳可查）

```
build_deps()                                   deps.py:250-310
  → env MODEL_ENDPOINT/MODEL_API_KEY/MODEL_NAME  deps.py:41-43、270-272
      缺一即 RuntimeError fail-fast             deps.py:274-275
  → gateway = _EnvModelGateway(...)             deps.py:281
  → register_capabilities(gateway=gateway, ...) deps.py:288-295
      → _register_media_capabilities(...)       capabilities.py:554
          → tool.vision.describe/elements/locate/ocr/classify   capabilities.py:664-700
          → tool.vision.compare                 capabilities.py:733-745（双图 handler :442）
              → vision_tools.py:102-194（原文 → 512px WEBP data URL）
                  → ask_vision()                vision.py:46-83
                      → Message(image_ref=...)  types.py:598,602-611（OpenAI 多模态 content parts）
                      → ModelGateway.complete() → provider.py:81-85 → httpx.post  ← 真实 HTTP
```

- **单一出口**：`ask_vision` 是视觉工具唯一的模型调用点（`vision.py:46`）；没有第二个 VisionPort，符合 ADR-003 Q9。
- **图片进 wire 的形态**：原文字节 → `_to_data_url`（`vision_tools.py:27-37`，Pillow 只读解码 + 512px 缩略图 + WEBP）→ `data:image/webp;base64,...` → `Message.to_dict()`（`types.py:602-611`）变成 `image_url` content part。**原文不直接进 prompt/日志**。
- **compare 的特殊处理**：`Message` 只支持单张图（`image_ref: str | None`），两图对比用 Pillow 横向拼成一张再送（`vision_tools.py:175-193`），**不扩展公共契约**。
- **无 key 时**：orchestrator worker 启动即 fail-fast（`deps.py:274-275`），预期行为，不是 bug。
- ⚠️ 上述链路全绿只能证明"给定图片能发出真实多模态 HTTP、输出能被解析"，**不证明**任何视觉识别质量。

## 2. 因缺真实视觉端点/key/权重无法真测的功能（6 项）

> 每项按"功能 / 为何无法真测 / mock 能验什么 / mock 不能验什么 / 真测所需 / 接线点"六栏登记。统一纪律：**mock 能验接线，不能验质量**。

### 2.1 `tool.vision.describe` — 自由描述

| 项 | 内容 |
|---|---|
| **功能** | 对图片做开放式描述/回答，返回模型文本（`vision_tools.py:102-109`）。 |
| **为何无法真测** | 无视觉端点/key/权重；mock 返回固定文本。 |
| **mock 能验什么** | ✅ prompt 拼装、data URL 生成、文本原样透传、降级时 `degraded=true` 且无输出。 |
| **mock 不能验什么** | ❌ 描述是否与图片内容相符、是否幻觉、细粒度属性（颜色/布局/数量）准确率。 |
| **真测所需** | ① 可用视觉模型端点（chat-completions 兼容、支持 `image_url` content part）+ key；② 描述标注集（图文配对）做事实一致性评测。 |
| **接线点** | `capabilities.py:664-670`；`vision_tools.py:102`；`vision.py:46`。 |

### 2.2 `tool.vision.elements` — 元素枚举

| 项 | 内容 |
|---|---|
| **功能** | 枚举 UI 截图中的界面元素，返回带可选 bbox 的元素列表（`vision_tools.py:112-122`）。 |
| **为何无法真测** | 无端点；且模型必须真实理解截图布局。 |
| **mock 能验什么** | ✅ JSON 解析、字符串/带框元素两种形态、非法框过滤、`refused_boxes` 计数。 |
| **mock 不能验什么** | ❌ 元素召回率/精确率、bbox 坐标是否真落在对应元素上、小字/密集 UI 的表现。 |
| **真测所需** | ① 视觉端点；② UI 截图 + 元素 bbox 标注集（如控件/按钮/文本区域），按 IoU 验收。 |
| **接线点** | `capabilities.py:672-678`；`vision_tools.py:112`；`_elements_from` `:54-73`。 |

### 2.3 `tool.vision.locate` — 对象定位（"抠人物"链路关键步）

| 项 | 内容 |
|---|---|
| **功能** | 定位指定对象并返回 bbox，供 `tool.image.crop` 按框裁出（ADR-014 U-1 的"抠第几秒某个人物"近似路径：`frame_at → vision.locate → crop`）。 |
| **为何无法真测** | 无端点；目标检测是最依赖模型质量的环节。 |
| **mock 能验什么** | ✅ target 非空校验、bbox 真值校验（有限/非负/宽高为正，`:39-52`）、非法框丢弃、找不到时返回空列表。 |
| **mock 不能验什么** | ❌ 指定人物/对象能否真被定位、bbox 是否框住目标、多人场景消歧、被遮挡目标表现。 |
| **真测所需** | ① 视觉端点；② 含目标对象的图片 + bbox 标注集，按 IoU/召回验收；③ 与 `frame_at`/`crop` 串联的端到端用例。 |
| **接线点** | `capabilities.py:680-686`；`vision_tools.py:125-140`；`_valid_bbox` `:39`。 |

### 2.4 `tool.vision.ocr` — 视觉模型读文字

| 项 | 内容 |
|---|---|
| **功能** | 用视觉模型识别图片文字（区别于本地 rapidocr 的 `tool.image.ocr`），返回文本行（`vision_tools.py:143-152`）。 |
| **为何无法真测** | 无端点；视觉 OCR 的准确率完全依赖模型。 |
| **mock 能验什么** | ✅ 元素数组解析为文本行、原始文本留证、降级不造假。 |
| **mock 不能验什么** | ❌ 真实文字识别准确率、艺术字/低对比度/竖排文字表现、与本地 OCR 的质量差异。 |
| **真测所需** | ① 视觉端点；② 多场景文字图片标注集，按 CER/WER 验收，并与 `tool.image.ocr` 做对比基线。 |
| **接线点** | `capabilities.py:688-693`；`vision_tools.py:143`；`_elements_from` `:54`。 |

### 2.5 `tool.vision.classify` — 候选标签分类

| 项 | 内容 |
|---|---|
| **功能** | 从调用方给出的候选标签中选一个，输出不在候选内的标签一律丢弃（`vision_tools.py:155-171`）。 |
| **为何无法真测** | 无端点；分类准确率依赖模型。 |
| **mock 能验什么** | ✅ 候选白名单过滤（真测过：越权标签被丢弃）、空 labels 校验、降级行为。 |
| **mock 不能验什么** | ❌ 真实分类准确率、相似标签区分度、open-set 场景表现。 |
| **真测所需** | ① 视觉端点；② 带类别标注的图片集，按准确率/混淆矩阵验收。 |
| **接线点** | `capabilities.py:695-700`；`vision_tools.py:155`。 |

### 2.6 `tool.vision.compare` — 两图对比

| 项 | 内容 |
|---|---|
| **功能** | 两图横向拼接后送模型做差异描述（`vision_tools.py:175-194`）。 |
| **为何无法真测** | 无端点；且对比理解是高阶视觉推理。 |
| **mock 能验什么** | ✅ 双 ref 的 hash 校验、拼图生成（Pillow）、单 message 单 image part、输出透传、降级。 |
| **mock 不能验什么** | ❌ 差异描述是否真实/准确、细粒度变化（颜色/位置/数量）识别、拼接是否影响模型判断。 |
| **真测所需** | ① 视觉端点；② 成对图片 + 差异标注集；③ 验证"拼图送单图"方案在真实模型上的效果，必要时改多图 content parts（需扩展契约）。 |
| **接线点** | `capabilities.py:733-745`；双图 handler `:442-460`；`vision_tools.py:175`。 |

## 3. 非模型缺口（单列，不混算到 §2）

| 缺口 | 性质 | 状态 / 说明 |
|---|---|---|
| **像素级人物分割**（透明背景抠图） | 能力范围外（ADR-014 U-1 排除） | `tool.vision.locate` 只给 bbox，`tool.image.crop` 按框裁剪是矩形区域，**不是像素级抠图**。真分割需分割模型（rembg/SAM）+ 权重，另立决策。 |
| **多模态结果回灌** | 上下文装配缺口（ADR-014 U-5） | 首版回灌的是文本 JSON（含 `frame_ref`/`crop_ref`），图片不直接进模型上下文；`Message.image_ref` 目前只在工具调用内部用于送图给视觉模型。 |
| **附件洞察槽注入** | M05→M07 既有待办（ADR-014 U-8） | `AttachmentInsightPort.insights()` 仅 Protocol 声明，生产未注入（`worker.py:133-145` 只注入偏好/程序记忆）；本套视觉工具不依赖该槽，靠结果回灌闭环。 |
| **`infra/deploy/model_providers.yaml` 能力矩阵** | 设计文档要求但未落地 | `设计方案.md`/M20 要求版本化供应商配置（含 `vision` 能力矩阵、缺项 fail-fast）；当前仓库 `infra/deploy/` 目录不存在，模型名由单一 `MODEL_NAME` 注入（`deps.py:43`）。 |
| **视觉 token 成本计量** | 可观测缺口 | 视觉调用的 image token 成本随 `ModelUsage` 归一（`provider.py:21-29`），但无按工具的视觉 token 分项账；`cost_hint`（140-180）是 L0 提示值，非真实计量。 |

## 4. 真测清单（配好端点后按此验收）

1. **连通性**：配 `MODEL_ENDPOINT/MODEL_API_KEY/MODEL_NAME` 指向支持 `image_url` 的 chat-completions 端点，跑 `test_m05_vision_tools.py` 去掉 mock，确认 6 个工具都能发出真实多模态请求。
2. **质量基线**：用 §2 各项标注集分别验收描述一致性、元素 IoU、定位 IoU、OCR CER/WER、分类准确率、对比差异召回。
3. **端到端**：`frame_at(第 N 秒) → vision.locate(人物) → image.crop(box)` 真跑一遍，验证"抠第几秒某个人物"近似链路在真实模型下可用（仍非像素级分割）。
4. **降级路径**：断网/错 key/端点不支持多模态时，确认 `degraded=true` 且不返回编造语义（mock 已验逻辑，真环境需复验）。
5. **成本**：核对视觉 token 真实用量与 `cost_hint` 的偏差，必要时补分项账。

## 5. 纪律复述

- **接线正确 ≠ 模型质量达标**：mock 全绿只证明封装/降级/校验机制正确。
- **不静默降级**：无端点 fail-fast（`deps.py:274-275`）；有端点但模型返回非法 bbox/越界标签时按代码过滤，不把脏结果当可信结论。
- **原文红线**：原文不进 prompt/日志，只经 512px 缩略图 data URL 送模型。
- **诚实登记**：本文件所有"未验收"项在模型端点接通前保持 Open，不得在文档/覆盖矩阵中写成"已真接线且质量达标"。
