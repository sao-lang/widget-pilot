## 2. 因缺少真实模型 key 无法真测的功能（核心标注）

### 2.1 agent loop 真实生成链路（M03 run() 经 M04 dispatcher 驱动）

| 项 | 内容 |
|---|---|
| **功能** | 提交描述 → 入队 → dispatcher 驱动 `run()` → 模型生成 → checkpoint 落 PG → 终态回写会话，全链路真实执行 |
| **为何本机无法真测** | `build_deps` 需 `MODEL_*` 三件套；本机未配真实端点/key，若强跑 worker 会 fail-fast；集成测试改注入 `FakeModel`（`tests/conftest.py` 脚本化 `set_script`）替代模型 |
| **mock 覆盖（已真测，335 passed 的一部分）** | `test_m04_dispatcher.py`：DONE→COMPLETED、ASK_USER→AWAITING_INPUT、失败不 ACK 留 PEL、重试计数+死信；断言真落 PG checkpoint + 回写会话（真连 PG/Redis，非假绿） |
| **mock 能验什么** | ✅ 队列消费、Deps 装配、run() 驱动、checkpoint 落库/恢复、终态映射、租约、幂等、审计——**编排与持久化全链路** |
| **mock 不能验什么** | ❌ 真实模型是否按预期产出 signal、生成质量、多轮对话一致性、真实 usage/成本计量、真实延迟与超时行为 |
| **真测所需** | ① `.env` 配 `MODEL_ENDPOINT/MODEL_API_KEY/MODEL_NAME`；② `docker compose --profile full up -d` 起 orchestrator；③ 提交真实描述走完整链路；④ 断言产物可渲染、signal 正确、成本入账 |

### 2.2 模型 signal 判定质量（DONE / ASK_USER / REPAIR / FAILED）

| 项 | 内容 |
|---|---|
| **功能** | 模型在 final JSON 里给 `signal`，`decide()` 据此进终态/澄清/回边；这是整条生成回路的"唯一不可信变量" |
| **为何本机无法真测** | 当前用 `FakeModel.set_script` 预置 signal（如 `test_m04_dispatcher.py` 的 DONE/ASK_USER），测的是"收到该 signal 后编排是否正确"，不是"模型会不会给出正确 signal" |
| **mock 能验什么** | ✅ signal→状态迁移的映射正确、白名单字段提取、usage 计入预算 |
| **mock 不能验什么** | ❌ 真实模型对描述/规格的 signal 判定准确率、澄清问题质量、回边是否合理、是否会误报 DONE（假产物） |
| **真测所需** | 标注集（描述→期望 signal），真实模型跑一遍算准确率；与 M06 §1.4 标注集校准共用 |

### 2.3 结构化输出与 usage 计量

| 项 | 内容 |
|---|---|
| **功能** | `provider.complete` 把跨供应商 usage 归一到 `Usage`，`normalize_usage` 处理 OpenAI/Anthropic 字段差异；`with_retry` 对 429/5xx 指数退避 |
| **为何本机无法真测** | 单测用 Synthetic usage / FakeModel 固定值；无真实 HTTP 响应可验字段解析与重试触发 |
| **mock 能验什么** | ✅ 重试次数上限、业务失败不重试、useage 归一函数逻辑（给定 dict 的输出） |
| **mock 不能验什么** | ❌ 真实供应商响应字段形态兼容性、真实 429/5xx 退避时序、真实 token 计数与成本账对账 |
| **真测所需** | 真实端点返回真实 usage；对账 M11 成本表；注入真实 429 观察退避 |

### 2.4 生成产物质量（DONE 的 bundle_ref）

| 项 | 内容 |
|---|---|
| **功能** | DONE 终态带 `bundle_ref`，repr 产物引用；M04 对空 `bundle_ref` 转 FAILED（`NO_VERIFIED_BUNDLE`，`dispatcher.py:45,263-273`），不假绿 |
| **为何本机无法真测** | FakeModel 给的 `bundle_ref` 是脚本字符串（如 `bundle-e2e`），无真实产物对象存储 |
| **mock 能验什么** | ✅ 空产物转失败、非空产物回写 COMPLETED 的分支正确 |
| **mock 不能验什么** | ❌ 产物是否真可渲染（需 M08 沙箱校验）、bundle_ref 是否指向真实对象、manifest 与 spec 一致性 |
| **真测所需** | 真实模型生成 → M08 沙箱编译/渲染/断言 → 产物落对象存储 → 回写 bundle_ref（M08 接入是独立边界，见 M04 指南 §10） |

> **非模型类缺口**（产物可信校验依赖 M08、澄清答案回注 checkpoint 依赖 M07）不属于"模型缺失"，
> 是模块边界尚未接入，记在 M04 指南 §10，不要混算到本节。
