# ADR-020：0 LLM 能力边界与结构化反问采集

> 状态：2026-11-25 22:58 设计批准（用户拍板）。权威范围：R3 路线定性 + P0/P1 止血边界。
> 与 ADR-013/016 的关系：ADR-013 定义三层解释器（规则→本地小模型→云端）；本 ADR 在**当前无真权重、无模型端点**的运行前提下，把"0 LLM"的可用能力边界正式定性，并规定缺信息的处理走反问而非硬猜。不改 ADR-013 的三层结构定义。

## 1. 背景与问题

2026-11-25 只读拷问（10 项要求逐条实测）确认：当前"0 LLM 意图识别路由"在**无真实模型调用、且无本地小模型权重推理**的前提下，存在四处结构性不满足——R2 缺槽反问、R3 乱序语义解析、R7 继续处理附件/取消在生成、R10 校验去重。其中 R3 是根因：

- `services/guardrails/interpreter/rule.py:39-65,132-251` 的"乱序解析"全部是 `re.finditer` + 词表最近邻，不是语义理解。
- `local_model.py:36-39` 缺权重即 fallback；`P3-本地小模型依赖与测试缺口标注.md:5-18` 明确生产从未实例化本地层。
- 用户诉求 R3 原文要求"不能依靠单纯的正则或者关键字进行匹配"，与"0 LLM 且无本地小模型"在逻辑上不可调和。

## 2. 决策

### D1 · R3 路线 = 结构化反问采集（降级满足，诚实标注）

**采纳**：正则只做意图族粗分与显式槽位（grid/host/data）提取；其余 9 类信息（数量/类型/样式/规格/交互/作用/功能/结构/附件用途/修改目标）以**显式槽位建模**，缺哪个就在反问链路里问哪个，让用户用自然语言补充后再次粗分，靠多轮交互收敛，不靠模型语义理解。

**定性**：这是 R3 的**降级满足**——系统不声称"理解了乱序自由文本"，只保证"不静默丢信息、不乱猜、缺则问"。任何"已实现乱序语义解析"的表述都禁止写入设计文档与覆盖声明。

**否决**：①引入本地小模型权重（违背用户当前约束，且无部署侧权重）；②伪装正则为语义理解（假绿）。

**D1 补充（2026-11-25 23:35 用户拍板）· 混排意图按片段语义分流**：
- 「桌面放个2x2天气卡片，**卡片怎么添加到桌面**」——后半段是问系统操作/教程（N5 教程族），**走反问**，给用户带两个原话片段确认执行哪个（如"您想生成 2x2 天气卡片，还是想知道卡片怎么添加？"）。
- ADR-004 硬样本「桌面放个2x2天气卡片，**显示今天天气怎么样**」——后半段是 widget 内容描述，不是操作咨询，**继续放行**（不反问）。
- 纯教程请求（无生成意图）→ 越界硬拒，不反问。
- 实现：`input_guard.classify_intent_mix()` 按分隔符+无标点边界切片段、逐段判生成/教程语义；混排返回 `HitDecision.AWAIT` hit，`validate_chain` 转 `CLARIFICATION_REQUIRED` → dispatcher `AWAITING_INPUT`。安全红线（注入/PII/敏感词/危险调用/预算）在混排判定**之前**扫，不被反问分支绕过。**注意**：`classify_intent_mix` 是 `check_input` 内部判据，不是端到端唯一判据——dev-context 整句拒绝等 step0 短路会先于反问；纯教程 `out_of_scope` 也硬拒不反问。反问带全部识别片段（不只两段）。

### D2 · 意图裁判唯一化（R10）

删除 `validate_chain.py` 的 step11 `classify_intent` 调用（v3 spec FR-11 已要求但一直未做），意图越界判定收敛到 step0 `is_out_of_scope` + step7 `check_input` 两处；`RuleInterpreter` 只做意图族粗分写 `SlotFill.intent_id`，不再自称"意图放行裁判"。

同时修复实测的硬样本误拒：ADR-004 硬样本「桌面放个 2x2 天气卡片，显示今天天气怎么样」在解释器判 compiled，却被 `check_input` 的 N5 教程族正则 `卡片.{0,8}怎么` 拒。修法是在 `check_input` 内做意图类命中的"显式生成动词+宿主+grid 正向优先"豁免（仅对 description 本身、不豁免附件提取文本、不豁免注入/PII），与 `_l1_rule_intent` 的正向优先口径一致。**否决**给 N5 加 `_NEG_WIDGET_GUARD` 前缀——该 guard 禁止宿主词而 N5 要求宿主词，二者互斥会让 N5 永久失效（复审 B1）。

### D3 · 槽位反问表（R2）

`SlotFill.slots` 从 grid/data/host 扩展出显式槽位键：`count`（数量）/`style`（样式）/`interaction`（交互）/`function`（作用功能）/`structure`（结构）/`attachment_purpose`（附件用途）/`target`（修改目标）；只抽取用户**显式说出**的维度；未说出的不追加 `missing_slots`（避免 8 连问死循环）——这是 D1 降级满足的具体含义。`missing_slots` 仍承载 grid/intent/target/附件等必需槽位，`question_kind=slot` 走结构化反问。

### D4 · 本轮边界（P0+P1）

本轮只做 D2（校验去重+误拒修复）与 D3（槽位反问）+ 本 ADR 文档；不改公共 JSON Schema、无 DB 迁移。D1 的运行语义（多轮反问收敛）作为"能力边界声明"固化，实际多轮交互编排不在本轮代码范围。

## 3. Open（登记未做，不_blocked 本轮）

- R7 取消在生成 + TSX 合并：需新在生成任务模型，成本高于收益； Owner=用户，待下一轮拍板是否立项。
- R8 二次失败确定性修复、R9 LLM 产物成包：分别依赖返工规则表扩展与 M07 成包回路； Owner=用户。
- 本地小模型权重与云端端点：部署侧提供，不在本项目代码范围； Owner=部署方。

## 4. 验收口径

- 硬样本不再被 `check_input` 误拒（回归测试）；
- `validate_chain.py` 无 `classify_intent` 调用（grep 0 命中）；
- 显式说出的 count/style 进 slots（泛指「整一个」不算）；缺 grid 时返回 `clarification` 且 missing_slots 含 grid（单测）；
- 全量 pytest / ruff / pyright / contracts drift 全绿。
