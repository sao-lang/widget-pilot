# ADR-019：P1 收尾 · generation_path 可观测性与产物引用口径

> 状态：2026-11-25 20:05 设计批准，实施中。权威范围：P1 剩余三项（#37 两项 + #38）。
> 与 ADR-013 的关系：ADR-013 定义确定性通道与三口径统计；本 ADR 只定"统计标签怎么落"与"产物引用字段是什么口径"，不改 ADR-013 的生成语义。冲突表述以本 ADR 为准并回写 ADR-013 §8。

## 1. 背景与问题

P1 清理中深查发现三个缺口，其中两个基于**错误假设**，必须先纠正：

1. **generation_path 只在日志**：`dispatcher.py:477-482` 得了 path 仅 `logger.info`，不进任何 durable 载体；`llm_fallback`/开关 off/异常分支无 path；`rejected`/`failed` 被误标 `deterministic`。ADR-013 §4 的三口径统计（一次通过率 / 含确定性修复 / 含 LLM 返工）无法从生产数据算出。
2. **bundle_ref "丢 hash" 是伪问题**：原假设"下游按 object ref 解析会失败"**撤回**。实测 `session.bundle_ref` 生产仅 1 读取点（`server.py:934` 原样透传），`parse_object_ref` 调用点全是 M08/bundle 内部 ref；M09 全端点按裸 `bundle_id` 精确等值，喂带 hash ref 直接 403。真实问题是 LLM 路径产物引用无校验、契约漂移、`source_ref`/`compiled_ref` 内部混用。
3. **LLM 路径未串三门禁**（#38）：`run.py:392-400` 终态仍是模型自报 `bundle_ref`，`dispatcher.py:541` TODO 未闭合。门禁只在确定性路径生效。

## 2. 决策

### D1 · generation_path 主载体 = cost_ledger 加列

理由：`cost_ledger` 是全仓唯一「每 run 一条、durable、`run_id` 唯一幂等」的记录（`models.py:479` + `pg_ledger.py:49 ON CONFLICT DO NOTHING`），三口径统计本就该挂在它上面 `GROUP BY generation_path`。加列范式现成（迁移 0019 的 `_has_column` 守卫 + `server_default`），**不碰公共 JSON Schema，contracts:check 零漂移**。

否决方案：事件 payload（`events.schema.json` 无 done 专属分支、SDK 生成物 `z.unknown()`、Redis 窗口 500 条过期、前端零消费——写进去只是换个地方不可观测）。

### D2 · path 载体 = CostEntryMeta（不进 State）

`CostEntryMeta`（`cost/ports.py:47`，注释明确"State 之外的元数据"）新增 `generation_path` 字段；`State`（packages/agent_core）不引入该字段，保持分层。`_try_deterministic` 把局部 path 提为分流结果的一部分随分支带出。

值域（封闭）：`deterministic` / `cloud-fallback` / `llm-only` / `llm-rework`。修正 `rejected`/`failed` 误标（门禁失败不是"确定性生成成功"，应标 `deterministic` 之外的失败语义——用 `deterministic` + branch 字段区分，不新造值）。

### D3 · occurrence 表补全非终态漏斗

新增轻量 `generation_occurrence` 表（run_id + session_id + generation_path + branch + created_at），记录**每次分流决策**，含 clarification 挂起、开关 off、通道异常（这些不落成本账）。成本账只记终态成本，occurrence 记全分支漏斗，职责分明不做双写对账。统计从 occurrence 算，成本账提供成本维度关联。

### D4 · bundle_ref 口径 = 裸 bundle_id 单一口径（不改格式）

- 状态链四处（`session.bundle_ref` / `generation_task.result_ref` / `current_bundle_ref` / `task_turn.result_bundle_ref`）同源同值，均为裸 `bundle_id`，**保持不动**。
- `source_ref`（带 hash）与 `compiled_ref`（纯 key）都在 bundle 内部字段，hash 留在内部，状态链只存 id——语义分明。
- **否决**"统一成带 hash object ref"：仓内无该格式生成方；M09 全端点按 id 等值，带 hash 会 403；会造成事件/契约/撤销锚点四处破坏。

### D5 · LLM 路径产物校验 + 三门禁（#38 与 D4 共根因）

`run.py` 终态只信模型自报 `bundle_ref`。彻底做法：DONE 前校验 `bundle_id` 在 `widget_bundle` 真实存在且属于该用户（`BundleService.get`），否则不置 DONE。同时把 M08 `validate_and_test` 串进 LLM 路径终态（复用确定性通道同一函数，不重复校验确定性命中）。这是"裸 id 口径"从约定升级为有约束口径的关键。

### D6 · 修契约漂移

契约声明 `bundle_refs[]` 无人生产、REST 返回契约未声明的 `bundle_ref` 单值。决策：**契约如实声明单值 `bundle_ref`**，删除空壳 `bundle_refs[]`，与实现和消费对齐；跑四同步（gen:python/zod/openapi/enums）。

## 3. 影响面

- 迁移 0020（`cost_ledger.generation_path` 列 + `generation_occurrence` 表）；head→0020，revision id ≤32 字符。
- `CostEntry`/`CostEntryMeta`/`meter_adapter`/`pg_ledger`/`models.py` 同步加字段。
- `_try_deterministic` 返回值带 path；dispatcher 各分支埋 occurrence。
- `BundleService.get` 校验接入 LLM 终态；三门禁串接。
- 契约 openapi + 四同步。
- 不扩散到 P5 返工代码（llm-rework 值预留但不产生）。

## 4. 验收

- 全量 pytest 零回归；ruff/pyright 非外部目录 0；contracts drift=[]；source_purity --strict 新目录 0。
- 统计测试：`GROUP BY generation_path` 能从 cost_ledger 复算三口径；occurrence 覆盖 clarification/off/异常分支。
- 契约测试：单值 bundle_ref 在 openapi/SDK/Python 三处一致；bundle_refs[] 已删。
- LLM 产物校验测试：不存在/越权 bundle_id 不置 DONE。
