# ADR-001 · 规格输入方式改造、执行中询问用户通道、意图识别级联强化

> **状态**：已接受（用户确认，2026-11-16）
> **影响范围**：全部 22 份模块文档（`docs/modules/`）与 `设计方案.md` 对应章节
> **决策性质**：修改原 v1.1 的两条定稿表述（「规格一等输入、用户显式选择、系统不推断」；「模型处理不了 → 转人工」），新增一条成本决策。不改变分层架构、不新增服务、不引入 Agent 框架（D-5 仍成立）。
> **版本标记**：本决策起模块文档集进入 **v1.3**；与本文冲突的旧表述一律以本文为准。

---

## 1. 背景

原设计（v1.1）的三条相关定稿：

1. **规格是一等输入，由用户显式选择，系统不推断**——前端新建会话必须选 grid，否则不可提交；
2. **模型处理不了 → 自纠正 ≤2 次 → 转人工（HANDOFF）**——生成过程中没有向用户提问的通道；
3. **意图识别为纯代码规则（M06 `input_guard.py`）**——规则未覆盖的长尾描述只能靠「描述充分性校验」兜底，覆盖不足时要么误拒、要么放行进主 LLM。

用户决策（2026-11-16）：规格不再强制前置选择，缺了就问；模型执行不了/不确定/无法做的，都问用户；加强意图识别模块权重，降低 LLM 成本。

**社区主流方案调研结论**（2026-11，公开资料）：生产环境降低 LLM 成本的主流模式是**级联路由（Cascade Routing）**——① 规则/正则路由（零 token 零延迟，做 fast-path 与安全拦截）→ ② 语义路由（本地小 embedding 模型 + 意图样本库余弦相似度 + 阈值，毫秒级近零成本，代表开源实现 `semantic-router`）→ ③ 便宜小模型分类器兜底（仅低置信时调用，受 token 上限约束）→ ④ 前沿大模型仅作最后手段。公开报道该模式可节省 70–85% 推理成本。注意两条反模式：不能用模型自报置信度当升级判据（校准性差）；升级率过高（>20–30%）说明层级设计失效。本项目原铁律「确定性门禁高于模型自律」与「不把模型自报置信度当路由判据」与该模式完全兼容。

## 2. 决策

### D-6 · 规格输入方式：可选预填 + 缺省询问，绝不推断

- 前端 `GridSelector` **保留但可跳过**；`POST /api/sessions` 允许 `grid=null` 创建会话。
- 规格获取优先级（在 M06 语义层执行，纯代码裁定）：
  1. 用户用选择器选定 → `grid_source="selector"`；
  2. 描述文本中含明确规格线索（"4x4"、"两行两列"等），经**规则词表**确定性映射 → `grid_source="explicit_text"`；
  3. 二者皆无 → **不推断**，置 `AWAITING_INPUT` + `SPEC_MISSING`，`notice` 事件携带 `suggest_grid`（按描述中控件类型的典型密度给出建议项），用户回答后 `grid_source="clarified"`。
- `Session.grid` 改为**可空列**；进入生成回路（M07）前 grid 必已确定（不变量 I-G1：`RUNNING` 态必有 `grid != null`）。
- 「六种规格约束 layout_slots / 尺寸断言 / 前端真实比例」的下游语义**不变**；变的只是「规格何时、由谁、如何确定」。

### D-7 · 执行中询问用户：受控 `ask_user` 通道

- 新增结构化澄清机制。触发主体有两类：
  - **确定性代码触发**（M05/M06，原有能力扩展）：附件 role 不明、描述不足、规格缺失；
  - **模型触发**（M07 生成回路新增）：模型遇到**执行不了的任务、不确定的信息、无法做的事情**时，产出一次结构化 `ClarificationRequest`。
- 模型触发约束（防滥用）：
  - 问题必须是**封闭式**（≤3 个选项或短文本补充），围绕当前任务，禁止询问与任务无关信息；
  - 每任务 **≤2 次**（计入 `clarify_count`，与自纠正回边分立计数），每次计入轮次与 token 预算；
  - 问题文本过出护栏校验（无 PII、无内部实现泄漏）；
  - 会话转 `AWAITING_INPUT`，推 `ask_user` 事件（`AgentEventKind` 17→**18** 种）。
- 用户通过 `POST /api/sessions/{session_id}/clarifications` 回答，答案作为附加上下文槽位（`clarification_answer`）回注生成回路继续；`decide()` 新增 `ASK_USER` / `RESUME_FROM_CLARIFICATION` 分支。
- **转人工收窄**：`HANDOFF` / `HUMAN_REQUIRED` 仅保留给「询问次数用尽仍无法继续」「回边超限且无法通过询问解决」「检索无结果且询问不能弥补」三类场景。
- `decide()` 仍是纯函数；询问是显式状态转移（`GENERATING → AWAITING_INPUT → GENERATING`），checkpoint 记录 `clarify_count`，跨天恢复后可继续回答。

### D-8 · 意图识别四级级联（加强 M06，降低 LLM 成本）

M06 意图识别由「纯规则单层」升级为四级级联，每级的判定结果（命中层、置信度、耗时、成本档）写入 trace 与 `routing` 事件：

| 级 | 机制 | 成本 | 职责 |
|---|---|---|---|
| L1 | 规则路由：关键词/正则/槽位词表 + 注入/PII/意图白名单硬规则（词表扩充并版本化） | 0 | 安全拦截必过；高置信意图直接裁定；规格线索抽取 |
| L2 | 语义路由：本地小 embedding 模型 + 意图样本库余弦相似度 + 版本化阈值 | 近 0（毫秒级） | 规则未命中的长尾描述归类；意图集合封闭（`WIDGET_GENERATION` / `CLARIFICATION_ANSWER` / `OUT_OF_SCOPE` 等） |
| L3 | 便宜小模型分类器兜底（`ModelGateway` 低档端点，token 上限受控） | 低 | 仅 L2 置信度不足时调用；输出意图 + 结构化置信区间 |
| L4 | 主 LLM | 高 | 仅 L1–L3 均无法裁定时；**白名单拒绝类（OUT_OF_SCOPE / 注入 / PII）永远在 L1 拦截，绝不进任何模型** |

- embedding 模型与小模型分类器经 M20 Provider 抽象接入（新增 embedding 与 classify 端点能力位），版本纳入 `repro_fingerprint`。
- 升级率、各级命中率、成本节省纳入 M11 指标与 M19 评测（意图路由准确率 / 误放行率 / 升级率 / 端到端成本 P95）；阈值影子期校准、版本化、可回滚（沿用 D-4 机制）。

## 3. 契约影响汇总（由 M02 收敛到 `packages/contracts/`）

| 变更 | 内容 |
|---|---|
| `Session` | `grid: GridSpec \| null`（可空）；新增 `grid_source: "selector" \| "explicit_text" \| "clarified" \| null`、`clarify_count: int` |
| `ReasonCode` | 新增 `SPEC_MISSING`（规格缺失待询问）、`CLARIFICATION_REQUIRED`（执行中需澄清）、`CLARIFICATION_LIMIT`（询问次数用尽）；计入 Q1 同批收敛 |
| `AgentEventKind` | 17 → **18**：新增 `ask_user`，payload `{ question_id, question, options?: string[], allow_text: bool, clarify_count, clarify_limit }` |
| REST | 新增 `POST /api/sessions/{session_id}/clarifications`（body: `{ question_id, answer }`）；`POST /api/sessions` 的 `grid` 改为可选 |
| `WidgetSpec` | schema 注释由「用户显式选择，不推断」改为「可选预填 + 缺省询问补全，系统不推断（ADR-001 D-6）」 |
| 内核 | `decide()` 新增 `ASK_USER` / `RESUME_FROM_CLARIFICATION` 分支；M03 GATE 用例同步 |

## 4. 后果

- 正面：入口摩擦降低（不必先懂规格再提问）；长尾意图在模型前被廉价裁定，frontier 调用显著减少；模型卡住时可向用户要信息而非直接失败，任务完成率上升。
- 代价与风险：多一轮交互延迟（可用 `suggest_grid` 一次点击缓解）；询问通道可能被模型滥用（以 ≤2 次硬上限 + 出护栏校验约束）；语义路由样本库需要冷启动语料与持续维护（影子期校准 + M19 回归门禁兜底）。
- 回归范围：M02 契约、M03 `decide()` 分支、M06 级联、M07 询问回边、M04 状态机、M13/M14 前端交互、M10 硬过滤前置条件、M19 评测维度——任何后续变更触发对应模块回归。
