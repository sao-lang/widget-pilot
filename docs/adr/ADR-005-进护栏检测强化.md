## §1 设计意图

- 进护栏必须**零模型、确定性、可留证**；不把安全判定交给 LLM 自报。
- 规则表负责「形状召回」，成熟库负责「真值判定」——两者互补，避免只看正则导致误报。
- 敏感词按类别分流：涉黄/涉暴可用通用分类词做基础召回；**涉政词库刻意不内置**，由合规方经外部 JSON 提供，防止代码仓库成为词库事实源。
- 命中只留类别引用，不写敏感词原文；同一文本命中多个类别时按文本顺序只取**首个**（留证简洁优先，告警聚合另属 M11）。
- 命中留证不写敏感词原文，只写类别引用（`<sensitive:CATEGORY>`）。

## §2 背景与库选型

现状：`patterns/injection.py` 3 条、`patterns/pii.py` 3 条；PII 只匹配形状，形似但无效的号码会误报；无敏感词检测。

调研结论（2026-11-21）：

| 候选 | 结论 | 理由 |
|---|---|---|
| LLM Guard | **否决** | 2026-07 已归档，不再维护 |
| Guardrails AI | **否决** | 商业收购后 hosted validators 下线，Hub 安装路径关闭 |
| NeMo Guardrails | **否决** | Colang 学习成本 + 模型调用延迟，与零模型门禁冲突 |
| Presidio | **部分采纳思路** | PII 能力强但默认英文 + spaCy 模型；中文需另建 NLP 管线，成本过高 |
| phonenumbers / id-validator / email-validator / pyahocorasick | **采纳** | 成熟、轻量、职责单一；PII 做真值判断，敏感词做 O(n) 多模式匹配 |

来源：https://static.runit.ai/blog/llm-guardrails-compared 、https://github.com/iiTzAK/toolmask/blob/main/docs/comparison.md （库维护状态与能力边界）；具体版本以 `uv.lock` 为准。

## §3 范围与边界

- **范围内**：注入规则扩充、PII 真值校验适配器、分类敏感词检测、GuardHitType.SENSITIVE、依赖与 stub、测试与文档同步。
- **范围外**：不改出 LLM 护栏、沙箱代码校验、模型侧安全分类；不内置具体涉政词表；不改 ReasonCode/事件 schema/SDK 契约。

## §4 交付内容

1. `patterns/injection.py`：3 → 8 条规则，新增越狱角色、编码外泄、分隔符注入、间接注入标记、凭据外泄。
2. `validators.py`：`is_valid_pii(rule_id, value)`——手机号 `phonenumbers.parse(..., "CN")` + `is_valid_number`；身份证 `id_validator.validator.is_valid`；邮箱 `email_validator.validate_email(check_deliverability=False)`。
3. `rule_registry.scan`：形状命中后再过真值校验，不通过则跳过该规则。
4. `sensitive.py` + `patterns/sensitive_lexicon.json`：`SensitiveWordDetector` 用 Aho-Corasick 扫描 PORN / VIOLENCE / POLITICAL 三类；POLITICAL 默认空数组。
5. `input_guard.check_input`：新增 `sensitive_detector` 可注入参数（None 用进程级默认实现，非内存桩），扫描顺序 = 注入/PII → 敏感词 → 意图白名单 → 预算。
6. `types.py`：`GuardHitType.SENSITIVE`；命中 excerpt 写 `<sensitive:CATEGORY>`。
7. 依赖：`pyproject.toml` + `uv.lock` 新增 4 个运行期库；`typings/` 下补 `ahocorasick` 与 `id_validator` stub（零 `type: ignore`）。
8. 去类型化收尾：删除 `intent_hints.py` 的 `_HINT_PATTERNS`，`validate_chain.widget_type` 恒 `WidgetType.CUSTOM`，字段仅为契约兼容保留。

## §5 敏感词外置协议

`WIDGETPILOT_SENSITIVE_LEXICON_PATH` 指向 JSON，结构与内置文件相同（category → 词数组）；启动时**按类别覆盖**内置词库（不是词级追加）。文件不存在或结构非法 → fail-fast，不静默放行。涉政词库必须由合规方提供，代码与测试只用中性占位词验证机制。

## §7 风险与未完成项

- 规则表仍无法覆盖未知注入变体；I14 与最小权限设计仍是主防线。
- PII 真值校验只覆盖手机号/身份证/邮箱三类；姓名、地址等需 Presidio/NER 时另立方案。
- 涉政词库为空是**刻意设计**，不是漏实现；上线前必须由合规方提供并走回归门禁。
- 依赖变更要求重建 `widgetpilot/python-base:dev` 与服务镜像（当前 Docker 未运行，登记环境阻断）。
