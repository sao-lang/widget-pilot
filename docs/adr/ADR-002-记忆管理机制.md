# ADR-002 · 记忆管理机制（偏好学习、证据留痕与遗忘）

> **状态**：已接受（2026-11-16）
> **影响范围**：M07（主承载）、M06（规格建议接入偏好）、M02/01（契约与基线）、M11/M19（指标与评测）、M04/M13/M14（端点与前端入口）、`设计方案.md`
> **决策性质**：补齐 v1.1 遗留缺口——`UserPreference` 只有「读 + 清」，没有「写 / 学习 / 冲突消解 / 遗忘」。本决策不引入任何 Agent 框架或记忆服务（D-5 仍成立），不新增 `ReasonCode` 与 `AgentEventKind`，不新增服务。
> **版本标记**：本决策起模块文档集进入 **v1.4**；与本文冲突的旧表述一律以本文为准。

---

## 1. 背景

v1.3 及之前的设计里，记忆（X3 / FR-23）只有三个动作：

- `UserPreference` 存 `{ palette, preferred_grids, preferred_widget_types, version, updated_at }`；
- 第 ⑥ 步上下文装配把它作为六槽位的**第 5 槽「用户记忆」**注入 prompt；
- `DELETE /api/users/me/preferences` 可清空并 `version+1`。

**缺口**：全链路没有任何「谁、在什么时候、从什么信号，把什么写进偏好」的定义。后果有三：

1. 偏好永远是空表，第 5 槽长期无用；
2. M06 `SPEC_MISSING` 的 `suggest_grid` 只按控件类型的典型密度给建议，**用户真实常用规格没有被利用**（记忆读了却没用在刀刃上）；
3. 「偏好可清除」在只有读端点时只是理论能力。

**社区主流方案调研结论**（2026-11，公开资料）：

| 方案 | 核心机制 | 可借鉴点 | 不采纳的原因 |
|---|---|---|---|
| **Mem0** | 抽取式记忆层；写入时 LLM 四操作 `ADD`/`UPDATE`/`DELETE`/`NOOP`；hash 去重 + 向量；SQL 记审计；检索融合语义 + BM25 + 实体 + 时间；Memory Decay 是**检索期重排**（近期 ×1.5、久未访问 ×0.3，不删除）；TTL + 定期把情节整合为语义摘要 | 四操作语义、写入时冲突裁定、检索期衰减、审计可查、按 `user_id`/`run_id` 作用域隔离 | 逐轮 LLM 抽取违背本项目「加强确定性、减少 LLM 成本」；引入独立记忆服务违背 D-5 |
| **Zep / Graphiti** | 双时态知识图谱（事件发生时间 + 摄入时间），边带有效期；冲突时**失效旧事实而非删除**，保留审计轨迹 | 「失效不删除」的冲突消解；可追溯的有效期 | 图数据库写延迟 300–500ms/轮、运维成本高；本项目偏好是**少量结构化字段**，无多跳关系推理需求 |
| **LangMem** | 类型化 semantic / episodic / procedural 事实 + 后台 manager 持续整合 | 分层类型化、后台整合思路 | 绑定 LangGraph 运行时（D-5 禁止 Agent 框架）；procedural memory 会让模型自改规程，破坏「规程是确定性资产」 |
| **Letta（MemGPT）** | OS 式 core / recall / archival 分层，agent 主动分页换入换出 | 工作记忆与长期记忆分离 | 需要完整有状态 agent runtime，运行时锁定；本项目会话态已有 M04 checkpoint |
| **Cognee** | ECL 图原生管线 + memify 按反馈重加权 | 反馈驱动的置信度调整 | 同为图系统，超出本项目需求 |

**关键失败模式（社区共识，必须规避）**：① 陈旧事实（用户改了偏好但旧值仍在）；② 语义记忆与情节记忆混存（「用户偏好 4x4」≠「用户 3 月 4 日提到过 4x4」）；③ 硬删除丢审计 vs 逐句软写产生重复。

**成本数据（Mem0 公开基准）**：选择性检索 5–10 条/调用约 $0.05–0.15/session，全量回放约 $0.50+/session，可降 60–80% 推理成本。本项目偏好字段本来就极少（三条字段），只要**不做 LLM 抽取、只注入高置信字段**，成本几乎为零。

## 2. 决策

### D-9 · 三层记忆边界（各司其职，禁止混存）

| 层 | 载体 | 生命周期 | 内容 | 边界 |
|---|---|---|---|---|
| **工作记忆** | M04 `Run` / checkpoint / SSE 事件流（Redis + PG） | 会话内，断点恢复 | 当前 super-step、`clarification_answer`、回边状态 | 已有，本决策不改 |
| **情节记忆（证据层）** | `PreferenceEvent` 只追加表（PG） | 默认 TTL 180 天（影子期校准），**到期失效不删行** | 「何时 / 何会话 / 从何种信号 / 学到或撤销了哪个字段的什么值」 | **不存对话原文、不存附件原文、不存代码** |
| **语义记忆（偏好层）** | `UserPreference` 结构化字段（PG） | 长期，随版本更新 | `{ palette, preferred_grids, preferred_widget_types }` + 每字段的证据引用与权重 | 只存枚举/短字符串；**禁止 `history_code` 类字段** |

**隔离铁律**：记忆**不进公共语料**、公共语料**不进记忆**（分别归 M07 与 M10，物理与逻辑双隔离）；历史经验的沉淀只走 M10 的脱敏语料 RAG，绝不回喂历史代码（延续 FR-23 / X3 硬约束）。

### D-10 · 偏好写入：规则优先、显式优先、零 LLM 抽取

写入信号白名单（只有这四类，其余一律 `NOOP`）：

| 优先级 | 信号 | 来源 | `source` 值 | 权重 |
|---|---|---|---|---|
| 1 | 用户在偏好设置里显式修改 | `PUT /api/users/me/preferences` | `explicit` | 1.0 |
| 2 | 用户在规格缺失 / 模型澄清卡上点选的回答 | `POST /clarifications`（结构化 answer） | `clarification` | 0.8 |
| 3 | 用户对规格预览卡 / 附件 role 的纠偏 | `PATCH /attachment-roles` 及规格预览卡纠偏 | `correction` | 0.7 |
| 4 | 用户采用 / 安装产物时，其 `WidgetSpec.palette` | M09 安装事件 | `adopted_artifact` | 0.3 |

**明确禁止**：① 从自由文本做 LLM 抽取（不调用任何模型，`call_count == 0`）；② 从附件原文 / `extracted` 文本学偏好；③ 从公共语料学偏好；④ 从被删除或回滚的产物学偏好；⑤ 用户关闭共享后的产物仍可作为采纳信号（关闭共享只影响语料入库，不影响本人偏好，但删除/回滚必须反向撤销）。

写入采用 Mem0 四操作语义的**本地化、纯代码版本**（冲突在**写入时**裁定，不留到检索时）：

| 操作 | 触发 | 行为 |
|---|---|---|
| `ADD` | 该字段当前为空 | 写值 + 写 `PreferenceEvent`，`version+1` |
| `UPDATE` | 同字段有新值且 `source_weight ≥` 当前值权重；或同权重但更新近 | 覆盖字段值；旧值所在事件标记 `superseded_at`（**不删行**）；`version+1` |
| `NOOP` | 新信号权重低于当前值、或字段值无变化、或信号不在白名单 | 不写偏好表，仅记一条 `PreferenceEvent(decision="NOOP")` 供审计 |
| `DELETE` | 用户清除（全字段或指定字段）/ 采纳证据被删除或回滚 | 字段置空；相关事件标记 `revoked_at`（**不删行**）；`version+1` |

**权重不变量**：低权重信号**永远不能覆盖**高权重信号（I-M3）；同权重按 `created_at` 取新。这样「用户显式设过 4x4」不会被后续一次弱采纳信号悄悄改掉，同时用户再次显式修改仍可覆盖。

### D-11 · 检索期衰减与读取门禁（不删除、只降权）

- 第 5 槽只注入**高置信字段**：`source_weight ≥ 0.7` **或** `evidence_count ≥ 2`；低置信字段不进 prompt（避免噪声）。
- 检索期重排（借鉴 Mem0 Memory Decay，纯代码、零成本）：最近 30 天被访问/强化的证据权重 ×1.5；超过 180 天未访问的 ×0.3；**只影响注入排序与入选，不删除任何行**。
- 每字段注入时附 `source` / `version` / `evidence_count`，便于产物解释「为什么用了这个偏好」。
- token 预算：第 5 槽总量计入 M07 四维预算的 `token` 维；超预算时按权重降序截断，不挤占 1–2 槽 caching 前缀。
- `repro_fingerprint` 新增 `preference_version` 项：同题、同偏好版本两次跑结果一致；偏好变化属于可解释的输入变化，不算复现失败。

### D-12 · M06 规格建议接入偏好（修复 v1.3 缺口）

`SPEC_MISSING` 的 `suggest_grid` 生成顺序改为确定性三段：

1. **首选** `UserPreference.preferred_grids`（去重，按最近使用倒序）；
2. 过滤掉与当前控件特征的冲突组合（沿用 `spec_conflicts.py` 冲突矩阵）；
3. 不足 ≤3 项时，再按 `widget_type` 典型密度表补齐。

不变量 I-M5：存在 `preferred_grids` 时，其合法项**必须**出现在 `suggest_grid` 首位；偏好为空时退回 v1.3 行为。这保证「记忆读了就用」，且仍**不推断**——偏好只影响建议顺序，最终规格仍由用户点选确认（`grid_source="clarified"`）。

### D-13 · 遗忘、撤回与可解释

- `DELETE /api/users/me/preferences` 全清（或 body 带 `fields` 单字段清除）→ 读取为空、`version+1`、事件日志保留但标记 `revoked_at`；清除后可审计但不可再注入。
- 用户删除 / 回滚控件 → M09 发信号 → `adopted_artifact` 类型证据失效 → 重算该字段：若无其他有效证据则置空 + `version+1`（防「从已撤回产物学到的陈旧偏好」）。
- `PreferenceEvent` 只追加、带 `user_id` 租户隔离与 `trace_id`，M11 审计可答「谁在何时从何种信号写入了什么」；**事件内容不含 PII 原文、附件原文与代码**。
- 全局 TTL 只让证据**失效**（不再参与权重计算），不物理删除，保留审计轨迹（借鉴 Zep「失效而非删除」）。

## 3. 契约影响汇总（由 M02 收敛到 `packages/contracts/`）

| 变更 | 内容 |
|---|---|
| REST | 新增 `PUT /api/users/me/preferences`（body:  Partial<Pick<UserPreference, `palette` \| `preferred_grids` \| `preferred_widget_types`>>，本人）；`DELETE` 支持可选 `fields`；`GET` 不变 |
| `UserPreference` | 每字段升级为 `{ value, source, weight, evidence_count, updated_at }` 的证据化结构（或等价的并列元数据字段）；`version` 保留 |
| 新表 `PreferenceEvent`（只追加） | `user_id`, `session_id?`, `field`, `old_value`, `new_value`, `source`, `source_weight`, `decision`(`ADD`/`UPDATE`/`NOOP`/`DELETE`), `superseded_at?`, `revoked_at?`, `trace_id`, `created_at` |
| `ReasonCode` / `AgentEventKind` | **不新增**（偏好是同步 CRUD，错误复用 `INPUT_INVALID` / `403`；不新增事件种类） |
| `repro_fingerprint` | 新增 `preference_version` 项（v1.4 复现口径） |
| M03 `decide()` | **不改**（偏好学习发生在生成完成后的确定性后处理，不进入决策函数） |

## 4. 不变量（可断言）

| # | 不变量 | 断言方式 |
|---|---|---|
| I-M1 | 偏好表与事件表不含 `history_code` / 附件原文 / PII 原文字段 | schema 断言 + 抽样扫描 |
| I-M2 | 偏好学习全流程 LLM 调用次数 = 0 | Fake ModelGateway 调用计数 |
| I-M3 | 低权重信号不能覆盖高权重字段值 | 权重矩阵表驱动单测 |
| I-M4 | 清除后读取为空且 `version+1`，事件日志仍可审计 | 端点断言 + 事件表断言 |
| I-M5 | 有 `preferred_grids` 时 `suggest_grid` 首位为其合法项 | M06 用例断言 |
| I-M6 | `preference_version` 进复现指纹；同版本同结果 | 复现指纹对比断言 |
| I-M7 | 租户隔离：`user_id` 过滤生效，跨用户偏好不可读/不可学 | 越权用例 |

## 5. 评测与观测（M11 / M19）

| 指标 | 口径 | 目标 |
|---|---|---|
| 偏好采纳率 | 用户后续实际选择命中偏好建议的比例 | 影子期建立基线，逐版提升 |
| 误学率 | 写入后 30 天内被用户反向纠正 / 清除的比例 | 逐版下降；> 阈值回滚权重 |
| 清除后残留率 | 清除后再注入命中该用户偏好的次数 | **0** |
| `suggest_grid` 命中率 | 点选偏好建议占全部 `SPEC_MISSING` 回答的比例 | 影子期建立基线 |
| 记忆注入 token 成本 | 第 5 槽平均 token / session | ≤ 预算 5% |
| LLM 抽取调用次数 | 偏好学习路径调用模型数 | **0**（I-M2） |

回归触发源：`source_weight` 阈值 / 衰减参数 / `PreferenceEvent` schema / `suggest_grid` 顺序规则任一变更 → 触发 M10 回归门禁（与 ADR-001 D-8 意图级联同机制）。

## 6. 取舍与明确不做

- **不做** LLM 逐轮抽取、不做向量库、不做图数据库、不做 Agent 框架/记忆服务（D-5、成本、运维复杂度）；
- **不做** procedural memory（规程是确定性资产，模型不得自改）；
- **不做**跨用户共享偏好（与公共语料严格隔离）；
- **不新增** `ReasonCode` / `AgentEventKind` / 服务；
- 未来自愿升级路径：若确需从自由文本学偏好，必须另开 ADR 证明「不违反确定性门禁 + 成本可控」，且默认走 L3 低档小模型分类而非主 LLM。
