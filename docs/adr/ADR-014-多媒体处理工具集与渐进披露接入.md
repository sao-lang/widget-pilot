# ADR-014：多媒体处理工具集（图片 / 视频 / 文案）接入 ADR-003 渐进式披露

**状态**: 2026-11-25 v1.3 已落地（用户跳过选择题，授权 AI 按项目惯例拍板 U-1～U-8；v1.0 只出设计，v1.1 按用户「直接补充工具函数并接进渐进披露」指令完成改码，v1.2 按用户「加一组处理 csv 的 tools」新增 7 个 CSV 工具，v1.3 按用户「把调用视觉模型也封装成一组 tools」新增 6 个视觉模型工具，均全门禁通过）
**范围**: 在 ADR-003 的统一 `Capability` 抽象上，新增一套给 LLM 用的常用图片 / 视频 / 文本处理工具，支持"按秒定位取帧"；补齐 ADR-003 遗留的"L2 结果未回灌 prompt"断点，使渐进披露真正闭环
**技术栈摘要**: Python 3.13 / Pydantic v2 / Pillow / ffmpeg（imageio-ffmpeg 静态二进制）/ rapidocr-onnxruntime / 对象存储（S3）；零新增框架（沿用 M03 registry + M06 门禁 + X4 预算）
**关联**: 前置 `ADR-003-统一能力抽象与渐进式披露.md`（FR-1/2/4/5/10/11、Q6）、`M05-附件处理域.md`（§2.1 技术栈、§6.2 AttachmentInsight）、`M03-手写Harness内核.md`（§11.6）；关联代码 `packages/agent_core/tools/`、`packages/agent_core/loop/run.py`、`services/orchestrator/capabilities.py`、`services/control_plane/attachments/`
**变更类型**: 能力集扩充 + ADR-003 遗留断点补齐（不改 ADR-003 既有结论）
**设计权威**: 文件本身；改码时以本文 §5 工具清单、§7 架构、§8.2 回灌闭环为准

## §1 设计意图（Design Intent）

- **一句话意图**：让模型能用一组**常用、确定性、只传引用**的多媒体工具完成"看图/取帧/取字/解析文本"，并且只在需要时才看到完整参数 schema——常驻成本可控、执行结果真能回到下一轮 prompt。
- **设计原则**：
  1. **一个抽象，不另起注册机制**：所有工具都是 `kind="tool"` 的 `Capability`，走 ADR-003 的 L0/L1/L2 与同一道 M06 闸门；出现第二套 tool 注册表即违背。
  2. **只传引用，不传原文**：handler 入参只含带 `#sha256:` 的对象存储引用；派生帧/裁剪图/切片写回独立 `derived/` 前缀，原文不进参数、日志、审计、checkpoint。
  3. **分级披露**：L0 只给 id/kind/brief/cost_hint；L1 下发真实 `args_schema`；L2 才执行。L0 出现 schema、正文或 base64 即违背。
  4. **结果必须回灌**：L2 输出要变成下一轮的"不可信数据"消息进 prompt；只写 ref 不回灌等于工具白跑（这是当前真实断点，本 ADR 强制补齐）。
  5. **确定性的归代码，语义的归模型**：时间定位、裁剪、OCR、解析、切片全部纯代码；只有"画面里有什么/哪个人在哪个框"这类语义判断用视觉模型，且无端点时 `degraded=True` 不造假。
  6. **预算与门禁不可绕过**：新工具全部计入 tool_calls + token，全过五项闸门；`cost_hint` 上浮必须反映在 X4 计费里。
- **反意图**：不做像素级人物抠图（分割模型 + 权重，重依赖，另立决策）；不做通用 shell/网络/任意文件写（ADR-003 §1 反意图）；不把工具结果当指令执行；不把附件原文塞回 L0 或系统提示。

## §3 范围与边界

- **范围内**：① 14 个新工具的契约（id / brief / args schema / L2 行为 / 产物形态）；② 注册与 composition root 接线；③ L2 结果回灌闭环（断点 1）；④ 常量、安全、降级、审计；⑤ 缺口登记与验收方案。
- **范围外**：像素级人物分割（透明背景）；真实视觉模型端点与权重；前端预览/裁剪 UI；公共契约 schema 变更；改 `run()` 的 `decide()` 判定优先级；断点的生产端口注入实现（断点 2 是 M05→M07 既有待办，本 ADR 只声明本套工具**不依赖**它）。
- **反向排除**：不得为了"抠人物"引入 rembg/SAM 等重依赖；不得让工具 handler 直接读用户上传的任意路径；不得把 base64/原文塞进 L0 目录或 checkpoint。

## §4 技术栈

| 类别 | 选型 | 约束 |
|---|---|---|
| 图片 | Pillow（只读解码 + 像素上限 4096） | 沿用 `process_visual`；新增按 bbox 裁剪，输出写派生 key |
| 视频 | imageio-ffmpeg 静态二进制 + `ffmpeg -ss` 输入定位 | 单次调用、列表参数（无 `shell=True`）、超时 20s；定位取帧用输入侧 seek，不整段解码 |
| OCR | rapidocr_onnxruntime（可选依赖） | 缺失时 `degraded` + `insight_quality=0`，不跳过校验 |
| 文本 | 自研 csv/json 严格解析（`errors="strict"`，不 `eval`） | 行数上限 1000，注入模式脱敏复用 `slots.INJECTION_PATTERN` |
| 存储 | 对象存储 `derived/{user}/{session}/{run}/{kind}` + `#sha256:` | 原文 `att/.../original` 与派生 `derived/...` 前缀隔离，M10 入库门禁两者都拒 |
| 校验 / 框架 | Pydantic v2 / FastAPI / pytest | 沿用，零新增框架 |

## §5 工具清单（权威契约）

命名约定：`tool.<媒体>.<动作>`；所有工具 `surface={"generation"}`、`kind="tool"`、`max_output_chars=4096`（大产物走引用）。L0 摘要行格式沿用 `CAPABILITY_LINE_TEMPLATE`。

### 5.1 图片（4 个）

| id | brief（L0） | cost_hint | L1 args（要点） | L2 行为 / 产物 |
|---|---|---|---|---|
| `tool.image.inspect` | 图片元信息/主色/尺寸 | 60 | `source_ref`（必带 hash） | Pillow 只读解码 → `{format,width,height,mode,palette,layout_hint}`；超 4096px 抛 `INPUT_INVALID` |
| `tool.image.crop` | 按坐标框裁出图片区域 | 80 | `source_ref`, `box: [x0,y0,x1,y1]`, `padding: int=0` | 校验 box 在画布内 → 裁剪 → 写 `derived/.../crop.webp#sha256:...`；**只返回 `crop_ref` + bbox**，不回传图片字节。"抠出画面里某个人"的可实现路径 = `understand` 出 bbox → `crop` 按框裁 |
| `tool.image.ocr` | 区域化 OCR 与文字坐标 | 90 | `source_ref`, `min_score: float=0.5` | 复用 `process_ocr` → `{ocr_text, regions:[{text,bbox,score}]}`；结果恒当数据，不当指令 |
| `tool.image.understand` | 图片语义元素与位置描述 | 150 | `source_ref`, `prompt: str`, `want_boxes: bool=false` | 复用 `understand_image`；有真实端点返回 `elements`（`want_boxes` 时要求模型给出 `text + bbox` 的 JSON）；无端点 `degraded=true`、elements 为空，**不猜人物框** |

### 5.2 视频（5 个）

| id | brief（L0） | cost_hint | L1 args（要点） | L2 行为 / 产物 |
|---|---|---|---|---|
| `tool.video.probe` | 视频时长/分辨率/帧率 | 60 | `source_ref` | `ffmpeg -i` 解析 stderr 元信息 → `{duration_s,width,height,fps,codec,size_bytes}`；超时降级仅 `size_bytes` |
| `tool.video.frame_at` | 按秒精确取一帧 | 100 | `source_ref`, `at_seconds: float≥0`, `format: "webp"\|"jpg"="webp"` | `ffmpeg -ss <t> -i <src> -frames:v 1` → 写 `derived/.../frame_at_<t>.webp#sha256:` → 返回 `{frame_ref,at_seconds,width,height}`；**用户点名的"第几秒"能力** |
| `tool.video.keyframes` | 等间隔抽关键帧（带时间戳） | 120 | `source_ref`, `interval_s: float=1.0`, `limit: int=3≤MAX_KEYFRAMES` | `ffmpeg -vf fps=1/<interval>`，每帧输出显式 `{t_seconds,frame_ref}`；补齐现有 `frame_index` 无时间戳的缺口 |

| `tool.video.frames_ocr` | 指定时刻/关键帧的文字提取 | 130 | `source_ref`, `times_s: list[float]`（≤5）, `min_score` | 逐点 `frame_at` 后跑 `process_ocr` → `{frames:[{at_seconds,ocr_text,regions:[...]}]}`；带时间戳，供"第几秒出现某文字" |

### 5.3 文案 / 文本（5 个）

| id | brief（L0） | cost_hint | L1 args（要点） | L2 行为 / 产物 |
|---|---|---|---|---|
| `tool.text.parse` | CSV/JSON 严格解析为行 | 60 | `source_ref`, `format: "auto"\|"json"\|"csv"` | 复用 `process_data_source`；值保持字符串、不 `eval`、超 `MAX_TEXT_ROWS` 截断并标记 |
| `tool.text.stats` | 字数/行数/编码/语言粗判 | 40 | `source_ref` | 纯代码统计 `{chars,lines,columns,encoding,has_bom}`；语言只给启发式 tag，不下结论 |
| `tool.text.clean` | 规范化空白与注入脱敏 | 50 | `source_ref`, `drop_blank_lines: bool=true` | 去 BOM/统一换行/去控制字符；命中 `INJECTION_PATTERN` 替换为 `[已过滤指令注入]` → 返回清洗后文本（≤`MAX_TEXT_OUT`） |

## §6 Approaches

| 方案 | 做法 | 优点 | 取舍 | 结论 |
|---|---|---|---|---|
| A | 14 个工具全部注册为 ADR-003 `Capability`，补结果回灌闭环 | 一个抽象/一份门禁、结果真进 prompt、渐进披露闭合 | 改动跨 M03/M05/M06，需加消息回灌 | **采用** |
| B | 只扩现有 3 个 handler 的参数，不新增工具、不补回灌 | 最小改动 | 无法按秒定位/裁剪/文本处理；结果仍不回灌，模型看不见 | 否决 |
| C | 另起一套 `MediaToolRegistry` + 原生 function calling | 表达力略强 | 违反"一个抽象"、需改 M20 请求体、双份门禁 | 否决 |

选 A 的理由回溯 §1：用户要"一套工具 + 接进渐进披露"，只有 A 同时满足能力覆盖与披露闭环。

## §7 架构设计

### 7.1 链路

```
启动期  register_capabilities(gateway, blob_reader, derived_writer) → REGISTRY（首批 + 14 媒体工具）→ freeze_registry()
   ↓ L0 目录（brief/cost）装配进 prompt 第 2 槽
模型输出 {"signal":"LOAD_CAPABILITY","capability_id":"tool.video.frame_at","level":1,...}
   ↓ M06 五项闸门 → invoke.load() 下发 args_schema（渐进披露 L1）
模型输出 level=2 + args{source_ref,at_seconds:12.5}
   ↓ M06 闸门 → handler 读原文(hash 校验) → ffmpeg 取帧 → 写 derived/...#sha256 → 输出短 JSON
   ↓ 【本 ADR 新增】_append_capability_result_message() → 结果作为 [工具结果·不可信数据] 消息进 spec.messages
   ↓ 下一轮 decide() → CALL_MODEL 带着结果继续生成
```

### 7.2 分层职责

- **M03（`agent_core`）**：保留 `Capability` / registry / `invoke` / `run()` 语义；**只加**结果回灌消息构造（§8.2），不改 `decide()` 优先级与门禁。
- **M05（`control_plane/attachments`）**：`real_processors.py` 增加 `crop` / `frame_at` / `probe` / `text_*` 纯函数；`derived_writer` 复用对象存储。`vision.py` 保持接口不变。
- **M06（guardrails）**：无需改门禁逻辑，把 14 个 id 加进 allowlist 即可；`MAX_CAPABILITY_PER_TURN` / `MAX_CAPABILITY_TOKENS` 复用。
- **M07（orchestrator）**：`capabilities.py` 注册新工具；`deps.py` 注入 `derived_writer` 与 gateway；`worker.py` 不改（本套工具不依赖 `attachment_port`）。

### 7.3 关键决策 U 清单（用户跳过选择题，AI 拍板）

| # | 未决点 | 定论 | 理由 |
|---|---|---|---|
| U-1 | 抠人物口径 | **按秒取帧 + 视觉模型出 bbox + 按框裁剪**（可实现近似），不做像素级分割 | 用户要"比较常见的功能"，分割需权重与端点，重依赖另立决策 |
| U-2 | 交付方式 | **只出 ADR 设计，本轮不改码** | 用户明确"帮我设计一套出来"，且项目惯例是先 ADR 后改码 |
| U-3 | 工具数量 | 14 个（图片 4 / 视频 5 / 文本 5） | 覆盖常见功能，L0 一行一个不撑爆常驻预算 |
| U-4 | 结果回灌形态 | 追加 `system` 消息、恒标 `[工具结果·不可信数据]`；派生产物只给 ref | 与检索槽同口径；state 只存结论与引用；保 caching 前缀不变 |
| U-5 | 多模态结果回灌 | **首版只回灌文本 JSON**（含 `frame_ref`/`crop_ref`）；图片直接进模型上下文登记为缺口 | data URL 进 args/输出会撑爆预算，且现有 `understand` 已能读 ref 出语义 |
| U-6 | 旧 3 个附件工具 | **保留 id 不动**（`tool.attachment.image/ocr/video`），新工具并行注册 | 不破坏既有测试与 L0 目录稳定性；后续可合并另立决策 |
| U-7 | 音频/字幕 | 不做 | 超出"常见图片/视频/文案"范围 |
| U-8 | 断点 2（attachment_port 未注入） | 不在本 ADR 修，声明本套工具不依赖它 | 它属 M05→M07 既有待办；本套工具靠 §8.2 回灌闭环，两者独立 |

## §8 其他关键维度

### 8.1 安全红线

- `source_ref` 必须形如 `key#sha256:<hex>`；无 hash / 篡改 fail-closed（复用 `make_s3_blob_reader`）。
- ffmpeg / ffprobe 一律**列表参数调用**，禁止 `shell=True`；`at_seconds` 等数值参数先做 Pydantic 范围校验再拼参数。
- 数值坐标/时间不接受模型传路径、不接受相对路径穿越；派生 key 由 `run_id + 序号` 生成，模型无法指定。
- 文本类输出统一走注入脱敏；OCR / 视觉元素恒标不可信数据，**不做指令解析**。
- 大产物只回 ref；L0 与审计日志不含 base64 / 原文 / PII。
- 单工具超时 20s、视频≤10MiB、片段≤15s、裁剪≤4096px；超限返回业务失败让模型自纠正，不放行。

### 8.2 L2 结果回灌闭环（断点 1 的补法，**本 ADR 核心改动**）

`run.py` 的 `LOAD_CAPABILITY` 分支在 `load()` 成功后（`run.py:339` 附近）：

1. 保留现状：`_store_capability_result()` 写对象存储、`apply_capability_result()` 写 `tool_result_ref`（回放/审计仍需要）。
2. **新增** `_append_capability_result_message(state, capability_id, output, max_chars)`：
   - 构造 `Message("system", f"[工具结果·不可信数据] capability={id}\n{output}")`，`output` 已是 `truncate()` 后的短 JSON；
   - 追加到 `spec.messages` **末尾**（结论槽之后），不改前 1–6 槽字节 → 保住 ADR-009 的 prompt caching 前缀不变量；
   - 受 `MAX_CAPABILITY_TOKENS` 与 `max_output_chars` 双重约束，超限截断而非丢弃；
   - 与 `_append_denial_message`（拒绝分支）合并为统一入口 `_append_capability_feedback_message`，成功/拒绝都走它。
3. `decide.py` 不改：`CALL_MODEL` 默认分支本来就读 `spec.messages`，回灌后下一轮自然带上结果。
4. 验收锚点：`test_capability_result_reinjected`（执行后 `spec.messages[-1].content` 含工具输出前缀）、`test_l0_prefix_unchanged_after_reinject`（前 6 槽字节不变）。

### 8.3 降级矩阵

| 依赖缺失 / 故障 | 行为 |
|---|---|
| 对象存储 writer 未注入 | 注册期 fail-fast（生产）；测试显式注入内存 writer |
| 视觉 gateway 为 None | `understand` 返回 `degraded=true`、elements 空，不猜 bbox → `crop` 无框可用时由模型自纠正 |
| rapidocr 未安装 | `ocr` / `frames_ocr` 返回空 regions + `insight_quality=0` |
| ffmpeg 超时 / 非 0 | `frame_at` / `clip` 抛业务失败（可自纠正）；`probe` / `keyframes` 降级仅元信息并标记 `degraded` |
| 文本非 UTF-8 | `text.*` 抛 `INPUT_INVALID`（`errors="strict"`） |

### 8.4 审计与计量

沿用 `run.py:351-354` 的 `_record_capability_audit`（id/level/surface/decision/latency）+ X4 四维计量；新增的派生对象 key 写进结果 JSON 供审计回溯，不写原文。

## §15.2 视觉模型工具组（2026-11-25，v1.3，用户「把调用视觉模型也封装成一组 tools」）

- **通用层**：`vision.ask_vision(image_ref, prompt, gateway, suffix)` 抽出多模态调用（复用 ModelGateway，不另起 VisionPort）；`understand_image` 改为薄封装，旧签名/旧测试行为不变。`VisionAnswer{text,json_value,degraded}` 保留原始文本 + JSON 容错，不造假。
- **6 个工具**（统一注册在 `capabilities.py`，纯函数在 `attachments/vision_tools.py`）：`tool.vision.describe`（自由描述）、`elements`（元素+bbox）、`locate`（定位指定对象，"抠第几秒某个人物"链路中出 bbox 的那一步）、`ocr`（视觉模型读文字，区别于本地 `image.ocr`）、`classify`（候选标签内分类）、`compare`（两图对比）。
- **纪律**：原文→512px WEBP data URL 再送模型（原文不进 wire/日志）；模型输出恒当不可信数据；bbox 真值校验（有限/非负/宽高为正），非法框丢弃并计 `refused_boxes`；分类只接受候选标签；compare 用 Pillow 横向拼图（Message 仅支持单图，不扩展公共契约）；无端点 `degraded=true` + `insight_quality=0`。
- **接入**：args model + spec 并入 `capabilities.py`，能力总数 **33**（首批 6 + 媒体 14 + CSV 7 + 视觉 6）。
- **测试**：`test_m05_vision_tools.py` 9 项（降级/旧接口兼容/bbox 过滤/标签白名单/compare 拼图/端到端 handler）；既有注册总数断言 27→33。
- **仍未闭合**：真实视觉端点/key/权重仍无（mock 验的是封装与降级，不是识别准确率）。**完整缺口清单见 `docs/modules/视觉模型依赖与测试缺口标注.md`**（6 个工具逐项标注 + 非模型缺口单列 + 真测清单）。

## §15.1 CSV 工具组（2026-11-25，v1.2，用户「加一组处理 csv 的 tools」）

- **7 个工具**（统一注册在 `capabilities.py`，纯函数在 `attachments/csv_processors.py`，标准库 `csv`、零新增依赖）：
  `tool.csv.parse`（严格解析+有界预览）、`schema`（列类型/空值/唯一值推断）、`filter`（eq/ne/gt/gte/lt/lte/contains/startswith，数值优先比较）、`sort`（数值列数值排序、稳定平局）、`select`（选列投影）、`aggregate`（group_by + count/sum/mean/min/max）、`stats`（数值列描述统计）。
- **纪律**：严格 UTF-8 + BOM 去除、`csv.reader` 处理引号/转义、分隔符确定性嗅探（, ; tab |）、列数不符行跳过并计数、行数上限 `MAX_TEXT_ROWS`、预览上限 `MAX_CSV_PREVIEW_ROWS=200`、列上限 `MAX_CSV_COLUMNS=100`；单元格恒当数据不 eval；结构化结果走 JSON 回灌、不写派生对象。
- **接入**：args model 与 7 条 spec 并入 `capabilities.py` 的 `_register_media_capabilities()`（不另起注册模块），统一注册后能力总数 **27**（首批 6 + 媒体 14 + CSV 7）。
- **测试**：`tests/unit/test_m05_csv_capabilities.py` 10 项（含引号/分隔符嗅探/malformed 跳过/数值 vs 字符串比较/分组聚合/no-eval/有界预览/端到端 handler）；既有 media 测试总数断言 20→27。
