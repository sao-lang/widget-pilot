## 结论（一句话）
不建议把 apps/web 换成 Next.js：核心冲突在「SSR/RSC 模型 vs 客户端 event-sourced + SSE 长连接回放」「Next API Routes 服务端判定 vs BFF 不做鉴权判定」「Node 运行时部署 vs web 静态 CDN」，且迁移成本（测试栈/回放夹具/契约生成）高、收益（SEO/首屏）在本产品近乎为零。

## 折中路径
- 若诉求是 SEO/营销/文档站：另起独立 Next 应用，与工作台 SPA 分离，不混改 apps/web
- 若诉求是路由/布局：TanStack Router 或 React Router 即可，无需 Next
- 若诉求是 BFF：保留现有独立 apps/bff（职责已定），Next API Routes 收益有限且易越界鉴权
