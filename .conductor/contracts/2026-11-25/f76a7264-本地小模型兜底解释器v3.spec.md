# 本地小模型兜底 + 混乱描述解释器 v3.0 · 设计规格

**状态**: 已确认（2026-11-25 14:29 用户拍板：U-1 BIO 序列标注 / U-2 本地文件+env fail-fast / U-3 本地小模型不算 LLM（零云端口径）/ U-4 规则≥0.8+模型≥0.75 按实测调；本轮只出设计不改码）
**范围**: 把 v2 的「纯规则槽位编译器」升级为**三层解释器**——确定性规则 → 本地小模型 → 云端 LLM 兜底；重点解决实测暴露的两大痛点：分散槽位聚合、多 widget 实例归属（共现消歧），让混乱描述也能命中零云端 LLM 的生成路径。
**技术栈摘要**: Python 3.13 / onnxruntime 1.32（已在依赖）/ 本地序列标注或小型 seq2seq 模型权重（待定）/ 现有 contracts schema / PG+S3 / 零新增云端依赖
**关联**: ADR-016（本设计权威，新建）、ADR-015（v2 被本设计覆盖理解层）、ADR-013（确定性生成通道，依赖）、ADR-004（去类型化）、Snips NLU（确定性优先+概率兜底原型）
**变更类型**: 架构级补充设计（理解层加一层本地模型 + 解释器重设计）

---

## §1 设计意图

- **一句话意图**：用「规则先试、本地小模型补全、云端 LLM 最后兜底」三层解释器，把混乱的自然语言描述稳定翻译成结构化 SlotFill；前两层都不出本机，只有真解析不了才花云端 token。
- **设计原则**：
  1. **规则优先、模型补缺**：确定性规则能解的绝不调模型；本地模型只在「规则给出的槽位不完整或不可信」时介入（Snips 的 deterministic-first 共识）。
  2. **本地≠云端**：本地小模型（onnxruntime 权重）与云端 LLM 是两个不同档位；v2 的零云端 LLM 路径在规则层或本地模型层完成时仍然成立。
  3. **模型只填槽、不做安全裁判**：本地模型输出过 schema 校验 + 取值域约束 + 出护栏，绝不产生拒绝结论（沿用 I14 精神）。
  4. **共现消歧是解释器的核心**：解决实测假阳性——「桌面+卡片」是同一 widget 的两种说法，不是两个实例；用位置共现 + 连接词边界 + grid 数量联合裁定 N。
  5. **诚实标注模型缺口**：无权重时本地模型层降级为「不可信、跳过并告警」，绝不假装命中。
- **价值排序**：解析准确率 > 零云端 LLM 覆盖率 > 可复现性 > 成本 > 实现简洁。
- **反意图**：不把本地小模型做成通用 NLU；不让它做意图分类之外的安全判定；不假装已有模型权重。

## §2 实测基线（本设计的问题来源）

**探针实测（2026-11-25，24 条复杂描述）**：
| 测法 | 结果 | 暴露问题 |
|---|---|---|
| v1 词表「先切片再抽」 | 21%（5/24） | 槽位分散——grid 在「尺寸就 2x2 吧」、host/data 在别处，切片切碎 widget |
| v2「全局抽取」 | 直接 75% / 含追问 92% | 宿主计数假阳性（「桌面+卡片」数成 2 个 widget），实例归属不可信 |
| 现有 bigram embedder（默认 L2） | 9 条真实描述相似度 0.40–0.59，全 < 0.75 | **现有本地语义路由对真实描述不工作**，v3 本地模型必须是真权重 |

**家底**：`onnxruntime 1.32.0` 已在 `uv.lock`（M05 OCR 带入，跨 win/mac/linux wheel 齐全）；**无 embedding / 分类 / 序列标注模型权重**；M20 `Embedder` / M07 `IntentClassifier` 端口是空插槽，默认实现是 bigram / 恒不可解析。

**结论**：v2 的「纯规则」在槽位抽取上够用，但**实例归属与混乱描述聚合**需要更高的语言理解能力——这正是本地小模型该补的位置。

## §3 范围与边界

- **范围内**：三层解释器（规则层 / 本地模型层 / 云端 LLM 层）、槽位抽取与实例归属、共现消歧算法、本地模型端口与协议、模型权重加载与 fail-fast、模型输出校验（schema + 取值域 + 出护栏）、降级判据与告警、模型缺口标注。
- **范围外**：训练自己的模型（本轮只定义接口与接入，权重来源见 §10）；改公共 JSON Schema；改 `run()`/`decide()`/`Deps.model`；设备 API 真实调用。
- **反向排除**：本地模型不得输出 `OUT_OF_SCOPE` / 注入 / PII 判定；不得凭空造不在描述与附件里的槽位值；无权重时不得静默假装命中。

## §5 需求清单

### 5.1 解释器三层

- **FR-1**：`Interpreter` 协议：`interpret(description, attachments, fields) -> InterpretResult`，`InterpretResult ∈ {Compiled(SlotFill), NeedClarification, Fallback(reason)}`，含 `layer_used ∈ {rule, local_model, cloud_llm}`、`confidence`、`evidence`。验收：三实现的单测 + mock 计数。
- **FR-2**：**规则层** `RuleInterpreter`：复用 v2 schema + 全局槽位抽取；新增**共现消歧**——按「宿主词位置 + 连接词边界 + grid 位置 + grid 数量」裁定 widget 实例数，禁止「桌面+卡片」数成 2（实测反例）；分散槽位（grid 在句尾）按实例位置聚合。验收：24 条探针重跑，实例数正确；「桌面+卡片」判 1 个。
- **FR-3**：**本地模型层** `LocalModelInterpreter`：实现 `Interpreter` 协议，用 onnxruntime 加载本地权重，对「规则层未解析/低置信」的描述做槽位抽取（**BIO 序列标注**，U-1 已拍板）；输出过 schema 校验 + domain 取值域 + 出护栏，不合法则 `Fallback` 而非硬塞。验收：有 mock 权重时的注入测试；无权重时 fail-fast 并告警。
- **FR-4**：**降级判据**：规则层 `Compiled` 且 confidence≥阈值 → 直接用（零模型）；规则层 `NeedClarification` → 追问（不调模型）；规则层 `Fallback` 或 confidence<阈值 → 本地模型层；本地模型层仍失败 → 云端 LLM（`run()`→`CALL_MODEL`，`generation_path=cloud-fallback`）。验收：四档判据单测。
- **FR-5**：**缺权重行为**：本地模型权重缺失/加载失败 → 该层返回 `Fallback(LAYER_UNAVAILABLE)` + 告警，**不静默用 bigram 冒充**（现有 bigram 相似度实测 0.4-0.59 全不达标）。验收：无权重用例断言告警 + 降级路径正确。
- **FR-6**：**云端 LLM 兜底**（沿用 v2 FR-16/17）：`validation.ok=True` + `generation_path=cloud-fallback` → 现有 `run()`；产物门禁失败 fail-closed，禁二次降级。验收：mock gateway 计数按层区分（rule=0 / local=0 / cloud>0）。
- **FR-7**：**可观测**：日志/指标记录 `layer_used` / confidence / 降级原因 / 模型版本 / schema 版本；命中率按层统计，支撑「本地模型是否值得」的数据决策。验收：三层各自统计可查。

### 5.2 解释器重设计要点（针对混乱描述）

- **FR-8**：**分散槽位聚合**：grid/host/data/attachment 各自在句中任意位置命中后，按「最近宿主词 + 连接词边界」归入同一实例；不允许把「尺寸就 2x2 吧」当成独立 widget。验收：B 档 4 条复杂单 widget 全部正确聚合为 1 实例。
- **FR-9**：**后置 grid 分配**：「都是 2x2」「规格分别 4x4 和 2x1」这类后置 grid 按实例顺序分配，不新增实例。验收：D/E 档后置 grid 用例实例数正确。
- **FR-10**：**附件作为槽位源**：沿用 v2 FR-6 的 `role × kind → 处理器 → slot` 矩阵；附件解析产物与文字槽位一起送规则层与本地模型层。验收：CSV+图片+视频 OCR 三类填对槽位。
- **FR-11**：**与校验链的关系**：沿用 v2 的位置决策（护栏后、语义层前，一次解释多处消费），删 step11 `classify_intent`，`route_layer` 增 `INTERPRETER` 并区分层（rule/local/cloud）。验收：grep 无生产调用；ADR-004 硬样本在 L1 层仍绿。

### 5.3 诚实标注

- **FR-12**：模型缺口文档：`docs/modules/M06-模型依赖与测试缺口标注.md`（新建）登记本地模型权重来源、真测条件、mock 能验/不能验边界；不把「接线正确」当「模型质量达标」。验收：文档存在且六栏齐全。

## §6 Approaches

| 方案 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A 三层解释器（本设计） | 规则 → 本地小模型 → 云端 LLM | 覆盖率与成本兼顾；混乱描述有模型兜底；前两层不出本机 | 需真权重；模型依赖管理 | **采用**（用户要求） |
| B 纯规则（v2） | 只加 schema 与词表 | 零依赖 | 实测实例归属假阳性、混乱描述聚合弱 | 否决（用户要求加本地模型） |
| C 直接云端 LLM | 全交主模型 | 最省设计 | 每请求花 token；与专用 widget agent 定位冲突 | 否决（只作最后兜底） |
| D 只本地模型不要规则 | 全交小模型 | 设计简单 | 放弃 Snips 确定性 1.0 F1 层；简单描述也烧 CPU | 否决 |

## §7 架构

```
process_one → 护栏后
  → RuleInterpreter.interpret
      ├─ Compiled(高置信) → SlotFill → 语义层消费 → 生成（零模型）
      ├─ NeedClarification → AWAITING_INPUT 追问
      └─ Fallback / 低置信
           → LocalModelInterpreter（onnxruntime 真权重）
               ├─ Compiled(校验通过) → SlotFill → 生成（零云端）
               └─ Fallback
                    → 云端 LLM（run()→CALL_MODEL, generation_path=cloud-fallback）
  → 产物三门禁 → 成包 → finalizer
```

接线四问：①调用方=validate_chain 护栏后；②依赖=规则/schema/onnxruntime 权重/现有 run()；③信号消费=SlotFill 被语义层/规划器/spec 构造器/日志消费，layer_used 被指标消费；④闭环=描述+附件→InterpretResult→SlotFill→spec→门禁→bundle→终态。
